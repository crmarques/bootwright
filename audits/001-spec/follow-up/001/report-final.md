## 1. Executive summary

**Most audit work is done and well done; not all of it.** Both reviewers
find the remediation substantive, with strong failure-path tests on the
destructive and durable paths. They differ mainly in depth: the Claude
assessment examined every sub-part of each recommendation and found more
residual work (35 partial against 17), while the Codex assessment counted a
limitation stated accurately and carried by an open item as addressed.

The reports agree on 190 findings. Twelve differ only on whether an owner
choice narrowed the accepted correction; both find the accepted scope holds.
For the other 30, the final disposition takes the reading supported by
evidence at `896e8d8f2`: 23 Claude partials whose remainder an independent
re-check confirmed in code or text, three Codex partials (F06-01, R2-04-01,
F15-04), and four reconciled cases (F14-07, F07-07, F17-07, V2-15).

Consequential remaining work:

1. **Two High findings remain partial.** F17-03: D168's text says M2c is
   paused while `specs/milestones/m2.md:231` and the X160 record say it pauses
   nothing and X61 is listed in progress; the owner must say which holds.
   R2-04-01: realized arms rebind a rotated access credential through the
   recorded exit with a test, and the vCenter remainder is carried by B99.
2. **Two open defects on safety paths.** A signed URL is still accepted on
   the argument vector by `--from-url` although the specs forbid it (F11-08),
   and an in-operation root transaction never waits for the root lock, so a
   concurrent `status` can turn a block `failed` or `unknown` (F13-02).
3. **Carried safety and qualification debt** that neither report counts as
   a catalog finding but both name: shared-host foreign-domain quiescence
   (B567), persistent context incarnation (B568), partial Ceph enrollment and
   partial DB/WAL recovery (B659, B662), storage removal while hosts survive
   (B491), restore without seal-counter rollback (B103), the eight operator
   authoring tasks (B857) and the Ceph recapture identity live run (B867).
   Their documentation is truthful; the protections are absent.
4. **Guards weaker than their claims and silent narrowing.** The arm-identity
   test exempts any `*admission*` file and later KubeVirt code exploits that;
   several items closed whole while sub-parts were dropped without a decision.

## 3. Quality assessment

**Where both reviewers agree.** The strongest work is the lifecycle and
destructive-operation guards: physical target proof executed against
synthetic sysfs, power refusals before runtime entry, inconclusive removals
kept unknown, durable disk-boot intent, consumer-survival refusal before
registration, bridge and BMC claims, volatile store roots refused, and the
access-credential rebind decided per capability. Their tests check the
prohibited effect and the interruption, not only the happy path. API changes
are consistent and guarded by schema-walking tests (unions, enum casing,
reference suffixes, kind catalog), and the docs gates test themselves with
seeded violations. Owner decisions in D183 to D188 are traceable and applied.

**Where the Claude assessment adds depth.** It sampled every High and Medium
delivering diff and had both closures and open findings re-checked by
independent Opus reviewers. That depth found: residual sub-parts dropped
without a decision (F13-03, F13-08, F03-06, F03-09's fingerprint, F02-01's
check, F02-06, F17-05, F01-11, R2-05-08, F14-07); guards narrower than their
rule (the `*admission*` file exemption, a language-row test that sees only
plugins and `scripts/`, an unrealized table checked one way, an untested Stop
hook); spec and code disagreements left by partial edits (F11-08,
`access.unproved`, trust anchors classed as access credentials); and a
recorded claim in the remediation's favor that is wrong (X160's "M2c is not
paused" against D168's text).

**Where the Codex assessment adds depth.** It separates documentation,
decision, implementation and live acceptance more strictly, and names the
carried safety debt (section 2.3) as the most consequential open work. It
cautions that F10-03, CX-R4 and CX-API04 close by documenting a limitation,
not by removing it, and that synthetic second-implementation tests, scripted
replay and injected filesystems do not qualify another backend, native
idempotence or reboot durability. It found three remainders the Claude
assessment had closed (F06-01, R2-04-01, F15-04).

**Combined judgment.** In-tree remediation quality is good on the safety
paths and adequate on the corpus. The recurring defect is completeness, not
correctness: items closed whole while parts went untracked, and sibling pages
left stale. Operational confidence stays limited by the carried debt of
section 2.3 and by unrun live and operator gates. Neither report certifies
production readiness.
