# Getting Started

This guide walks through the smallest connected lab path: one OpenShift control
plane node on libvirt with an emulated Redfish BMC. It is only the first slice
of Bootwright's model; larger inputs can add managed machine OS installation,
shared services, Ceph storage clusters, storage exports, KubeVirt child
clusters, and post-install add-ons. The example is generated by the CLI,
validates as-is after you adjust local addresses and secrets, and shows the
object relationships used by larger environments.

## What You Need

- A Linux bastion host where you run `bootwright`.
- Passwordless or prompted `sudo` for Bootwright-managed state under
  `/var/lib/bootwright`.
- Libvirt available on the bastion or on a reachable service host.
- An SSH key the bastion can use to reach the service host.
- An OpenShift pull secret stored outside the input tree.
- A machine network, API VIP, and apps VIP that can be used by the lab.

Do not put pull secrets, private keys, kubeconfigs, tokens, or passwords in the
desired-state directory. The YAML names secrets; the bytes are written to the
local Bootwright context.

## 1. Install The CLI

Download the `bootwright` binary for your platform from
[GitHub Releases](https://github.com/crmarques/bootwright/releases), then
install it on your `PATH`:

```bash
chmod +x bootwright
sudo install -m 0755 bootwright /usr/local/bin/bootwright
bootwright version
```

Optional Bash completion:

```bash
mkdir -p "${HOME}/.local/share/bash-completion/completions"
bootwright completion bash > "${HOME}/.local/share/bash-completion/completions/bootwright"
source "${HOME}/.local/share/bash-completion/completions/bootwright"
```

Run Bootwright as your normal user. Do not run `sudo bootwright ...` directly;
the CLI re-executes through `sudo` only when it needs protected local state.

## 2. Create A Starter Input Tree

Generate a single-node lab:

```text
bootwright example init my-sno-lab --output ./my-sno-lab
```

The scaffold writes six files:

```text
my-sno-lab/
  environment.yaml
  shared/
    machines.yaml
    provider.yaml
    networks.yaml
    infra-component.yaml
  clusters/
    my-sno-lab/
      cluster.yaml
```

The scaffold uses `apiVersion: bootwright.io/v1alpha1` resources. The files are
safe to commit after you keep secret bytes out of them.

## 3. Understand The Input Objects

The beginner example uses six object groups:

| File | Objects | What to understand first |
| --- | --- | --- |
| `environment.yaml` | `Environment` | Fleet defaults, DNS base domain, service catalog, and secret names. |
| `shared/machines.yaml` | `Machine` | The service host and the cluster node. Machines own addresses, SSH, OS mode, and substrate binding. |
| `shared/provider.yaml` | `InfraProvider` | The libvirt substrate and VM profile used to create the cluster node. |
| `shared/networks.yaml` | `NetworkConfig` | The machine CIDR and NMState template rendered into installer input. |
| `shared/infra-component.yaml` | `InfraComponent` | Managed services on the service host: load balancer, DNS, and NTP. |
| `clusters/my-sno-lab/cluster.yaml` | `ContainerCluster` | OpenShift release, install platform, endpoints, networking, and node binding. |

The important rule is ownership: `ContainerCluster` owns install intent, while
`Machine` owns node facts and `InfraProvider` owns substrate facts. A provider
swap should not force unrelated cluster intent changes.

## 4. Edit The Required Values

Start with these fields:

| File | Field | Set it to |
| --- | --- | --- |
| `environment.yaml` | `spec.baseDomain` | A DNS base domain you control or route in the lab. |
| `shared/machines.yaml` | `Machine/bastion spec.addresses[]` | The SSH and cluster-network addresses of the service host. |
| `shared/machines.yaml` | `Machine/bastion spec.access.ssh.keyRef` | The secret name for the SSH key used to reach the service host. |
| `shared/machines.yaml` | `Machine/<cluster>-master-0 spec.addresses[]` | The static install IP for the node. |
| `shared/provider.yaml` | `spec.libvirt.uri` | The libvirt URI, usually `qemu:///system`. |
| `shared/provider.yaml` | `spec.libvirt.machineProfiles[]` | CPU, memory, and disk sizing for the node VM. |
| `shared/provider.yaml` | `spec.networkAttachments[].libvirt.bridge` | The bridge attached to the machine network. |
| `shared/networks.yaml` | `spec.machineNetwork[].cidr` | The cluster machine network CIDR. |
| `shared/networks.yaml` | `template.networkConfig.routes` | The default gateway for the node network. |
| `shared/infra-component.yaml` | `bindAddresses[]` | API and apps VIPs on the machine network. |
| `clusters/my-sno-lab/cluster.yaml` | `spec.distribution.release.version` | The OpenShift release version to install. |

Keep `Environment.spec.secrets` as names only. For the scaffold, the usual
secret names are:

| Secret name | Purpose | How it is supplied |
| --- | --- | --- |
| `openshift-pull-secret` | OpenShift pull secret | `bootwright secret set` |
| `<cluster>-cluster-admin-ssh-key` | Node SSH key pair | Generated by `bootwright secret sync` |
| `bastion-host-ssh` | SSH private key for the service host | External `file:` path |
| `bmc-credentials` | Credentials for emulated Redfish | `bootwright secret set` |

Validate after editing:

```text
bootwright validate -f ./my-sno-lab
```

Fix any diagnostic by editing the named object and field, then validate again.

## 5. Import A Context

A context connects a name to your desired-state directory and stores generated
state under `/var/lib/bootwright/contexts/<context>`.

```text
bootwright context init lab -f ./my-sno-lab
bootwright context current
bootwright status
```

`context init` records the absolute input directory path. The YAML is not copied;
future Bootwright commands read the files in place.

If you move the input directory, repoint the context:

```text
bootwright context init lab -f <new-input-dir> --yes
```

## 6. Set And Sync Secrets

Write the context-local secrets named by the YAML:

```text
bootwright secret set openshift-pull-secret --pull-secret ~/openshift-pull-secret.json
printf '%s\n' "${BMC_PASS}" | bootwright secret set bmc-credentials --username "${BMC_USER}" --password-stdin
bootwright secret sync
bootwright secret list
```

`secret sync` creates generated secrets and reports any declared material that
is still missing. Context-local secret material is encrypted at rest.

## 7. Record Host Trust

Bootwright uses strict SSH host-key checking for non-local durable machines.
Record trust before non-interactive runs:

```text
bootwright host trust
bootwright status
```

Interactive `preflight` and `apply` can ask before recording a first-use key,
but `--yes`, `--dry-run`, and JSON output never prompt. Automation should always
run `bootwright host trust` first.

## 8. Prepare And Check

Prepare the bastion host, run preflight checks, render effective state, and
preview the graph:

```text
bootwright bastion setup --yes
bootwright preflight all
bootwright render effective
bootwright plan
```

What each command does:

| Command | Purpose |
| --- | --- |
| `bastion setup` | Installs or verifies local tools Bootwright needs on the bastion. |
| `preflight all` | Checks desired state, host reachability, local tools, and prerequisites before mutation. |
| `render effective` | Writes the normalized desired state with defaults applied. |
| `plan` | Shows the apply task graph without mutating hosts or clusters. |

## 9. Apply

Run the normal convergence path:

```text
bootwright apply --yes
bootwright status --watch
```

`apply --yes` converges infrastructure, the OpenShift install, and any bound
add-ons selected by the input tree. A later re-run uses the same command:
matching recorded work is skipped, missing work is created, and unsafe drift
fails closed.

When the run finishes, inspect access information:

```text
bootwright cluster access
```

The command prints URLs, kubeconfig paths, and password retrieval commands. It
does not print kubeconfig or password bytes by default.

## 10. Use The Cluster Kubeconfig

To merge the generated admin kubeconfig into your user kubeconfig:

```text
export CLUSTER=my-sno-lab
export SRC="${TMPDIR:-/tmp}/bootwright-${CLUSTER}.kubeconfig"
export MERGED="${TMPDIR:-/tmp}/bootwright-merged-kubeconfig"

mkdir -p "${HOME}/.kube"
touch "${HOME}/.kube/config"
chmod 0600 "${HOME}/.kube/config"

bootwright cluster kubeconfig --cluster "${CLUSTER}" > "${SRC}"
chmod 0600 "${SRC}"
CTX="$(oc --kubeconfig "${SRC}" config current-context)"
oc --kubeconfig "${SRC}" config rename-context "${CTX}" "${CLUSTER}-admin"
KUBECONFIG="${HOME}/.kube/config:${SRC}" oc config view --flatten > "${MERGED}"
install -m 0600 "${MERGED}" "${HOME}/.kube/config"
oc config use-context "${CLUSTER}-admin"
```

Use a unique kube context name per cluster, such as `<cluster>-admin`.
