# M8 — OKD, upstream platform services and upstream Ceph

Deliver the community distribution and upstream projects covering the roles of
OpenShift Platform Plus, and standalone upstream Ceph. [D290](backlog.md#d290)
reserves this milestone. **Requires:** qualified Machine, cluster, add-on and
storage paths from M1–M4 as each item uses them. **Exit tier:** in-tree and
owner-accepted runs on a previously qualified non-VMware substrate. **Open
decisions:** artifact releases, supported profiles and project-specific
installation and trust mechanisms at promotion.

## Planned slices

None scheduled. Promote each implementation after its artifact and exit matrix
are fixed.

## Item detail

### B748

Implement the OKD distribution of the existing OpenShiftCluster kind through the
[cluster selection](../openshift-clusters.md#selection-and-refusal) and
[platform contracts](../api/openshift-clusters.md#platform-union-and-derivation).
Pin installer, client, OS and release-image coordinates from the OKD publisher.
Define availability, verification and mirrored delivery for each. Publish the
exact tested release, topology and differences in the coverage matrix. Exit
requires projection and wrong-artifact refusal tests, interruption and
continuation, cluster readiness, working access, and positive removal evidence.

### B1914

Map multicluster management, security, registry and cluster data services to
Open Cluster Management, StackRox, Project Quay and Rook/Ceph respectively.
For each choose a maintained release and record feature gaps against the
corresponding portfolio role, prerequisites, images, trust, machine-readable
readiness and owned resources. Use the existing [add-on lifecycle](../add-ons.md)
and capability dependencies. Exit requires a functional probe per service
(manage a cluster, obtain a security result, push/pull an image and bind/use a
volume), resume after interruption, and documented deletion or retention.

### B1915

Use the upstream arm of the [Ceph API](../api/ceph.md) and the existing
[storage lifecycle](../ceph.md). Specify release/container provenance,
registry trust and eligible host, storage and SSH modes. Qualify applicable
[coverage profiles](../ceph-coverage.md#profiles-and-capacity) with recovery,
health, verified data I/O and removal proofs. Record unsupported combinations,
including constraints of the native SSH trust path, before opening effects.
