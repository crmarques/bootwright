# M4 — IBM Ceph clusters on bare metal

Provision and destroy IBM Ceph clusters on bare metal, with the managed RHEL on
bare metal a Ceph host needs, on libvirt guests behind sushy-tools Redfish BMCs
or on physical hosts. The [product scope](../project.md#product-scope) names
bare metal through BMCs and open-source, Red Hat and IBM Ceph storage
distributions.

**Requires:** M1, whose BMC trust [X21](delivered.md#x21--bmc-trust-and-administrator-custody) delivered for [B73](#b73); M2, whose
[B55](m2.md#b55) file set [B80](#b80) needs; and M3, whose
[B62](m3.md#b62) to [B65](m3.md#b65) and [B70](m3.md#b70) the remainder
extends. The install arms [B74](#b74) to [B77](#b77) need only B73. **Exit
tier:** an emulated rehearsal on libvirt guests behind sushy-tools BMCs and
real hardware, each an owner-accepted acceptance-ledger row (D17). **Open
decisions:** which install arms a Ceph host needs, the first question of B80's
definition.

## Planned slices

None yet: B72 awaits its operator gate, B73 its host-key repair, and the next
items need definition.

## Item detail

### B72

**Owners:** Substrate and Managed OS, with Infrastructure services, Workspace
(media store), Controller (stage closures) and State reconciliation.
**Requires:** M1g, delivered. **Acceptance baseline:** `8aa4494`, where X11
landed.

One Bootwright-installed RHEL 9.8 Machine on a libvirt guest that boots its
installer through an emulated Redfish BMC. Consumer:
[`examples/lab-rhel`](../../examples/lab-rhel/README.md).

**Supported shape.** The M1f service set, one libvirt `InfraProvider` whose host
is the controller or an SSH-reachable OS-ready Machine and whose BMCs bind a
unicast address, and installed Machines whose Anaconda profile selects
`hostedTree` or no package source. `initialPassword`, `diskEncryption`, `fips`,
`fromSubscription`, `mirror`, `templateClone` and vSphere or KubeVirt providers
refuse before registration, so the served ISO is secret-free; a private-content
path must extend the frozen request without changing its shape. Bare metal is
[B73](#b73)'s.

**Capabilities.** [Provider host](../substrates.md#provider-host-realization)
with managed
[attachments](../api/machines.md#machine-profiles-and-network-attachments) and
[machine realization](../substrates.md#machine-realization) with a pinned
sushy-tools BMC per domain; the host-wide
[media store](../managed-os.md#media-store), which C17 was promoted into;
[installation](../managed-os.md#installation) from a per-machine ISO and DVD
tree under
[consumer publication](../infrastructure-services.md#consumer-publication),
proved by the guest agent; a disk-deleting destroy consuming `data-loss`; one
progress row per step and retained output for every adapter run.

**Exit evidence:** the `internal/substrate` admission tests for managed
attachments and BMC port ranges; capability planning goldens over
`examples/lab-rhel`; request round-trip, evidence-validation and refusal tests
for both capabilities; the engine suite for requirements, consumed
authorization, binding resolution, the inverted removal graph and the fresh
removal that supersedes a failed operation; media store bounds, fault injection
and cross-context freeze refusal; adapter protocol and module tests with fake
HTTP and virsh runners; the collection gates over the new roles, playbooks and
plugins; CLI goldens for the media commands and the authorization refusal; the
progress-row goldens over a step with sub-steps and the retained-adapter-log
suites for a completed run; `cmd/bootwright/lab_rhel_example_test.go`; and
`make check`.

**Operator gate** (emulated rehearsal): lab-rhel under a matching build
(staged apply, a settled replay, a removal refused while the guest runs,
`machine stop`, destroy, a fresh apply), then a host restart and `machine
start`. A row accepted before X19 lands is repeated on a build that contains
it, because X19 changes the Redfish effect path
([X19](delivered.md#x19--redfish-and-identity)); the same row
can meet [B49](m1.md#b49). A row accepted before X20 is repeated too, because
[X20](delivered.md#x20--substrate-port-pre-boot-proof-and-observations) moved the power-off into the substrate's boot
entry point and validates every port input when it runs. The 2026-09-17 run predates `c42ea10`, so it is an
[observation](../../.agents/knowledge/installation-completion-proof.md).

**Constraints left behind:** local `setup` retains no adapter output
(B46 ([X31](delivered.md#x31--recovery-setup-custody-refusals-and-adapter-defects))).

### B73

**Owners:** Substrate and Managed OS, with Infrastructure services, Machine and
State reconciliation. **Requires:** [B72](#b72), waived on explicit request by
2026-09-16. The physical installation on B72's Anaconda path, without M3 or
[B70](m3.md#b70).

**Deviation.** Physical managed-OS installation refuses before registration
until private host-key delivery is repaired: the Kickstart that names the
tokenized key URL is implanted in the unauthenticated installer ISO. Its
in-tree gates pass. The repair is this item's remaining work, over the BMC
trust [X21](delivered.md#x21--bmc-trust-and-administrator-custody) delivered: publish the installer ISO under the private
token subtree, or deliver the host key over another channel, which is an owner
decision. The commit that lifts the refusal sets the acceptance baseline.

**Supported shape.** A bare-metal `InfraProvider` whose Machines declare NICs,
boot NIC, management controller and root device, install through
`redfishVirtualMedia` and name the delivered `sshKeyPair`; `substrates` may be
empty and virtual and physical Machines may mix. B72's refusals stand;
`import-certificate` trust is unimplemented and refuses.

**Capabilities.** One [target derivation](../substrates.md#selection-and-refusal)
every consumer reads, so `machine start` honours `bmc.tls.verify`;
[physical realization](../substrates.md#physical-machine-realization), which
proves identity and MAC set and retains everything on removal; and
[physical installation](../managed-os.md#physical-installation), which consumes
`data-loss` on apply, re-proves the target before and inside the installer and
proves completion over SSH pinned to the key its
[private publication](../infrastructure-services.md#private-consumer-publication)
delivered.

**Exit evidence:** the `substrate` target-derivation tests (each arm's
controller, channel and requirement, and a consumer that reads only the derived
answer); the `substrate/baremetal` capability suite (identity and MAC proof, an
incomplete inventory left unknown, the claim key, a removal that retains and
consumes nothing, always-quiescent); the `managedos/installation` suite for the
physical arm (authorization on apply, private publication removed at
completion, delivered-key completion, the Kickstart's in-installer proof);
`internal/machine/power` honouring declared controller trust; the collection's
Redfish client suite against three firmware shapes, its system-inspection and
protocol suites; the `examples/lab-baremetal` acceptance; for the host-key
repair, delivery tests in place of the refusal test and
B39 ([X31](delivered.md#x31--recovery-setup-custody-refusals-and-adapter-defects))'s no-private-URL-in-public-artifacts rule; and `make check`.

**Operator gate** (emulated rehearsal): the
[lab-baremetal](../../examples/lab-baremetal/README.md) rehearsal, first proof
of the emulator's `EthernetInterfaces`. Real hardware is not this item's gate;
M4's exit tier reaches it through [B78](#b78) (D17)
([knowledge](../../.agents/knowledge/redfish-physical-bmc.md)). X19's Redfish client
assumes from documentation alone what the first physical controller must
confirm: the VmmControl Disconnect payload, the 12 times 5 s boot read-back,
the TaskState rule, the one-authority refusal of firmware that returns absolute
references under its own host name, and the manager-scoped and dual-view
shapes. Vendor actions under
`Actions.Oem` are read only after a firmware observation shows one.

The identity inspection documents no worst case: it makes one request per reported network interface, which the managed-OS margin covers only up to six interfaces (X26).

**Constraints left behind:** a
[residual race](../state-reconciliation.md#mutation-safety) between the last
controller proof and the installer's first write; physical destroy and erase
remain [B70](m3.md#b70), so removal retains the system; bonded or VLAN install
interfaces and FIPS profiles refuse as the
[managed-OS refusal table](../managed-os.md#refusal-table) lists ([B74](#b74),
[B75](#b75)); and two
contexts claiming one controller from different hosts are not coordinated.

Since X21 a physical Machine's virtual media defaults to `import-certificate`, whose import, settlement and restore flow, and the controller CA bundle as the only anchor, are proved only in-tree against the upstream sushy-tools and DMTF shapes; this item's acceptance runs qualify them on firmware. A manager-scoped virtual-media device that publishes no Certificates collection needs `established` or the per-Machine exception.

It also takes the structural module's rule that no private URL appears in a public artifact, moved from B39 ([X31](delivered.md#x31--recovery-setup-custody-refusals-and-adapter-defects)) on 2026-09-30.

Since X31 the installation's completion inspection runs before the private material is withdrawn, so a delivered-key installation's evidence reports private material still published and its postcondition refuses; nothing reaches it while physical installation refuses (found in X31).
