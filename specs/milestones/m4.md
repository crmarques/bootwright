# M4 — IBM Ceph clusters on bare metal

Provision and destroy IBM Ceph clusters on bare metal, with the managed RHEL on
bare metal a Ceph host needs, on libvirt guests behind sushy-tools Redfish BMCs
or on physical hosts. The [product scope](../project.md#product-scope) names
bare metal through BMCs and open-source, Red Hat and IBM Ceph storage
distributions.

**Requires:** M1, whose BMC trust [X21](delivered.md#x21--bmc-trust-and-administrator-custody) delivered for [B73](#b73); M2, whose
[B55](m2.md#b55) file set [B80](#b80) needs; and M3, whose
[B62](m3.md#b62) to [B65](m3.md#b65) and [B70](m3.md#b70) the remainder
extends. The install arms [B74](#b74) to [B77](#b77) need only B73. **Exit
tier:** an emulated rehearsal on libvirt guests behind sushy-tools BMCs and
real hardware, each an owner-accepted acceptance-ledger row (D17). **Open
decisions:** which install arms a Ceph host needs, the first question of B80's
definition.

[X38](delivered.md#x38--the-real-host-run-of-2026-10-05) completed B72, managed RHEL on
emulated bare metal, when the owner accepted its run of 2026-10-05 (D58).

## Item detail

### B73

**Owners:** Substrate and Managed OS, with Infrastructure services, Machine and
State reconciliation. **Requires:** B72, waived on explicit request by
2026-09-16 and completed by [X38](delivered.md#x38--the-real-host-run-of-2026-10-05); X21; D103 and D104. The
physical installation on B72's Anaconda path, without M3 or
[B70](m3.md#b70).

**Deviation.** Physical managed-OS installation refuses before registration
until private host-key delivery is repaired: the Kickstart that names the
tokenized key URL is implanted in the unauthenticated installer ISO. Its
in-tree gates pass. The repair is this item's remaining work, over the BMC
trust [X21](delivered.md#x21--bmc-trust-and-administrator-custody) delivered, and D103 chose it: the per-machine installer
ISO is published only under the private token subtree,
`private/os/<machine>/<token>/`, and withdrawn after completion; the
in-installer `curl --cacert` fetch stays; and private delivery requires a
verified controller-to-BMC leg, through `bmc.tls.verify` or a
`trustBundleRef`, because InsertMedia carries the token URL. The repair also
installs the delivered host key at its own type's path with an
`sshd_config.d` drop-in and pins the type the controller verifies, since a
FIPS-mode controller cannot use Ed25519; and it runs the completion inspection
after the private material is withdrawn (found by the 2026-10-05 audit). X45
delivers it on the owner's request (D60), and the commit that lifts the
refusal sets the acceptance baseline.

**Supported shape.** A bare-metal `InfraProvider` whose Machines declare NICs,
boot NIC, management controller and root device, install through
`redfishVirtualMedia` and name the delivered `sshKeyPair`; `substrates` may be
empty and virtual and physical Machines may mix. The
[managed-OS refusal table](../managed-os.md#refusal-table)'s refusals stand.
`import-certificate` trust, implemented since X21, is proved only in-tree, and
the owner's xFusion iBMC publishes no Certificates collection, so it needs
`established` ([B305](#b305), D104).

**Capabilities.** One [target derivation](../substrates.md#selection-and-refusal)
every consumer reads, so `machine start` honours `bmc.tls.verify`;
[physical realization](../substrates.md#physical-machine-realization), which
proves identity and MAC set and retains everything on removal; and
[physical installation](../managed-os.md#physical-installation), which consumes
`data-loss` on apply, re-proves the target before and inside the installer and
proves completion over SSH pinned to the key its
[private publication](../infrastructure-services.md#private-consumer-publication)
delivered.

**Exit evidence:** the `substrate` target-derivation tests (each arm's
controller, channel and requirement, and a consumer that reads only the derived
answer); the `substrate/baremetal` capability suite (identity and MAC proof, an
incomplete inventory left unknown, the claim key, a removal that retains and
consumes nothing, always-quiescent); the `managedos/installation` suite for the
physical arm (authorization on apply, private publication removed at
completion, delivered-key completion, the Kickstart's in-installer proof);
`internal/machine/power` honouring declared controller trust; the collection's
Redfish client suite against three firmware shapes, its system-inspection and
protocol suites; the `examples/lab-baremetal` acceptance; for the host-key
repair, delivery tests in place of
`TestLabBaremetalExampleRefusesItsInstallation` and
B39 ([X31](delivered.md#x31--recovery-setup-custody-refusals-and-adapter-defects))'s no-private-URL-in-public-artifacts rule; the
per-machine ISO served only under `private/os/<machine>/<token>/` and
withdrawn after completion; the completion inspection running after the
withdrawal; Kickstart goldens per key type (Ed25519, RSA, ECDSA P-256) with an
`sshd_config.d` HostKey drop-in, and `HostKeyAlgorithms` taken from the pinned
type; private delivery refused without a verified controller-to-BMC leg; the
[lab-baremetal](../../examples/lab-baremetal/README.md) README's
host-prerequisites section, naming the disk the media and hosted trees take,
the egress destinations and the unauthenticated-route requirement, the
listener hand check, the firewall ports by source (D110), the rule for a host
whose store an earlier build holds, the FIPS key types, the RSA-2048
serving-certificate workaround (D113) and the artifact unit's journal for a
failed fetch; and `make quick`, the collection's units and lint suites,
`make docs-check`, `make check`, `make race` and an independent review of the
diff.

**Operator gate** (emulated rehearsal): the
[lab-baremetal](../../examples/lab-baremetal/README.md) rehearsal, first proof
of the emulator's `EthernetInterfaces`. Real hardware is not this item's gate;
M4's exit tier reaches it through [B78](#b78) (D17)
([knowledge](../../.agents/knowledge/redfish-physical-bmc.md)). X19's Redfish client
assumes from documentation alone what the first physical controller must
confirm: the VmmControl Disconnect payload, the 12 times 5 s boot read-back,
the TaskState rule, the one-authority refusal of firmware that returns absolute
references under its own host name, and the manager-scoped and dual-view
shapes. Vendor actions under
`Actions.Oem` are read only after a firmware observation shows one. D60 sets
the runs that follow X45: a disposable RHEL 9.8 controller, this rehearsal,
then one xFusion server, recorded as an observation.

The identity inspection documents no worst case: it makes one request per reported network interface, which the managed-OS margin covers only up to six interfaces (X26).

**Constraints left behind:** a
[residual race](../state-reconciliation.md#mutation-safety) between the last
controller proof and the installer's first write; physical destroy and erase
remain [B70](m3.md#b70), so removal retains the system; FIPS profiles refuse
as the [managed-OS refusal table](../managed-os.md#refusal-table) lists
([B75](#b75)), and since
[B289](delivered.md#x41--lifecycle-results-the-controller-stage-installation-shapes-and-bounded-runs)
a bonded or VLAN install interface refuses before registration as that table
lists ([B74](#b74)); and two contexts claiming one controller from
different hosts are not coordinated.

Since X21 a physical Machine's virtual media defaults to `import-certificate`, whose import, settlement and restore flow, and the controller CA bundle as the only anchor, are proved only in-tree against the upstream sushy-tools and DMTF shapes; this item's acceptance runs qualify them on firmware. A manager-scoped virtual-media device that publishes no Certificates collection needs `established` or the per-Machine exception.

It also takes the structural module's rule that no private URL appears in a public artifact, moved from B39 ([X31](delivered.md#x31--recovery-setup-custody-refusals-and-adapter-defects)) on 2026-09-30.

Since X31 the installation's completion inspection runs before the private material is withdrawn, so a delivered-key installation's evidence reports private material still published and its postcondition refuses; nothing reaches it while physical installation refuses (found in X31). The repair moves the inspection after the withdrawal.

### B305

The owner's xFusion iBMC departs from the shapes X19's Redfish client was
written against (found by the 2026-10-05 audit from the owner's captures): it
echoes an inserted image without its non-default port, which the client
rejects, so every insert fails; it publishes no Certificates collection and a
read-only `VerifyCertificate`, so only `established` trust can work, and
Bootwright never checks that the BMC verifies; InsertMedia sends
`WriteProtected`, which its action information does not declare; a task's
`Messages` is one object, whose failure reason the client drops; an insert over
foreign media spends an attempt on `ConnectionOccupied`; the physical MAC proof
never ran on it, and its refusal names no NIC; no Redfish fixture models it;
the physical-BMC knowledge page contradicts the captures; the field lessons
that [B74](#b74) to [B77](#b77) need are kept only on the pre-rewrite branch;
the artifact server keeps no record of a BMC's fetch; and the iBMC has fetched
only from an RSA-2048 server, while generated serving certificates are P-256.
Under
`established` trust the client reads `VerifyCertificate` and
`HttpsTransferCertVerification` before the insert and refuses private delivery
when either reads false, the operator importing the CA out of band until
[B319](#b319) (D104); serving certificates stay P-256, and the knowledge page
records the RSA premise, its check and the `contextStore` RSA-2048 workaround
(D113). **Exit evidence:** a redacted `xfusion` shape built from the owner's
captures running every parametrized operation; an echo without the
non-default port matching, while an explicit different port still refuses; an
InsertMedia body of exactly `Image`, `Inserted` and `TransferProtocolType`; a
`Messages` object yielding its `MessageId`; a device presenting other media
released, and proved empty, before the first attach; the MAC refusal naming
missing declared NICs and failing member positions; the `established`
verification read-back refusing private delivery; the artifact server's nginx
golden logging completed requests without the URI to standard output, with
the error log kept at warn; a failed attach naming the BMC-side causes and the
artifact unit's journal; the knowledge page rewritten from the captures,
without host names or serials, and a pointer in each of B74 to B77 to the
pages that hold its field lessons; and the collection's sanity, units and lint
suites, `make docs-check`, `make check` and an independent review of the diff.

### B316

Storage topology, stretch and service-placement sites never resolve to
`Environment.spec.sites` (found by the 2026-10-05 audit). Every site resolves
against the Environment's sites. **Exit evidence:** admission tests, among
them a negative one over the multidc-platform example.

### B317

Every storage invariant, about 97 rules, carries one generic next step, and
Entitlement refusals are worded as storage modes or OS installation (found by
the 2026-10-05 audit). The generic remedy goes, each rule with an exact remedy
names it, and an Entitlement refusal names the product type and field, such
as a `redhat-ceph` Entitlement requiring its registry credentials. **Exit
evidence:** admission tests whose remediation names the field to change.

### B318

Nothing checks the controller host's firewall for Bootwright's listeners, so a
BMC or installer that a default zone blocks meets an opaque
`ConnectionFailed` while readiness, probing over loopback, passes (found by
the 2026-10-05 audit). The operator owns the firewall, and the docs list the
ports by source (D110); before [B78](#b78), `preflight controller --context`
and `plan` report, for each declared socket, whether the zone of its
endpoint's interface admits the port. Its definition decides whether a closed
port warns or refuses before registration. **Exit evidence:** preflight and
plan tests over a fake zone query, for an open and a closed port.

### B319

The owner's xFusion iBMC publishes no Certificates collection, so the default
`import-certificate` trust fails at insert, and until this item the operator
imports the artifact server's CA out of band (D104). The manager's
SecurityService root-CA import becomes a discovered method, with removal
through its delete action and privilege refusals named, before the first
real-hardware row. Its definition settles first whether the account
Bootwright uses holds the privilege the import needs, and which root
certificate slot is free. **Exit evidence:** Redfish client tests over
[B305](#b305)'s xFusion shape for the import, its removal and a privilege
refusal, and the slot read recorded before first use.

### B326

An installed Machine gets only what its Kickstart network line carries, and
[B289](delivered.md#x41--lifecycle-results-the-controller-stage-installation-shapes-and-bounded-runs)
refuses secondary addresses, MTUs, non-install bonds and
VLANs and extra routes (found by the 2026-10-05 audit). Applying the composed
NMState after installation, as the pre-rewrite implementation did, would carry
them; [B80](#b80)'s Ceph cluster networks need that, so this item comes before
B80 (D79). **Exit evidence:** an installation applying the composed NMState
after the installer, with replay and drift tests.
