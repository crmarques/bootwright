pre-OpenShift readiness program the owner started on 2026-09-26, the 2026-09
audit follow-ups, and the safety, recovery and operability items that serve no
single product milestone. The [product scope](../project.md#product-scope)
names no platform for it; it serves the
[design priorities](../project.md#design-priorities-and-non-goals) of least
privilege and fail-closed effects.

[B49](#b49). **Open decisions:** those the Requires cells of B175, B188, B206,

## Item detail

### B17

Per-invocation private scratch passed to every role, disjoint machine and
provider namespaces and hardened delete guards, before lifecycle concurrency
rises above one. Every lifecycle role's owner shares the work. **Exit
evidence:** a two-concurrent-installs test; B39's no-fixed-scratch-path rule.

It also takes the structural module's rule against fixed scratch paths, moved from B39 ([X31](delivered.md#x31--recovery-setup-custody-refusals-and-adapter-defects)) on 2026-09-30; the libvirt host and machine roles still create and remove the fixed `/run/bootwright-substrate` directory on every replay (found in X29).

The managed-OS installation's work area is also one fixed path, `/var/tmp/bootwright-install`, shared by every installation on a host; since X31 an apply clears it first and a removal deletes it, safe only while lifecycle concurrency is one (found in X31).

### B18

Bounded parallel block execution is delivered; what remains is the lock it
does not need but a reader does. A lifecycle operation holds the exclusive root
lock for its whole duration, so a concurrent read refuses; narrowing that to
the context lease alone would let a read such as `status` observe a running
operation. It needs [B17](#b17) and a cross-context concurrent-install test.
**Exit evidence:** concurrent-reader evidence for the narrowed lock, and proof
that an operation's own blocks still see one coherent record set.

### B19

One implementation of [the adapter result protocol](../architecture.md#the-adapter-result-protocol),
and one Ansible runner: a shared plugin base and one Go decoder over the
protocol table X11 delivered. Its hang clause landed as S14 in X14. Ten
per-capability action plugins each carry their own copy of the protocol's
phase dispatch, acknowledgement, group emission and postcondition rule, and
each is paired with a documentation-only module. Beside them,
`controller/ansiblelocal` is a second runner with a second protocol reader with
a different record bound and a `prepared` phase the lifecycle runner does not
have, so `setup` and the controller stage cross a different boundary from every
other block. A refusal that races the adapter's own non-zero exit can be
classified `failed` instead of `unknown`, and a controller refusal before
native authorization releases the adapter only at its next acknowledgement.
Collapsing both is mechanical but changes what every role emits and what fails
a run, and no in-tree gate proves an adapter's real host behavior. Postcondition
decisions stay in Go (D11); whether progress groups come from task tags through
a callback plugin instead of emission tasks changes what a role contains.
**Exit evidence:** one shared protocol implementation with its own unit tests;
one runner whose request, phases and failure semantics both consumers share;
per-capability evidence proved by its own tests; the collection sanity, lint
and integration gates; and a real-host apply and destroy before the old paths
are removed.

Since X29 the bare-metal identity rule lives both in the physical protocol action and in Go's evidence decoder, like the other per-capability copies this item tracks.

Since X31 the lifecycle protocol decoder also accepts a `refused` record limited to the reasons a run request lists; the merged decoder carries both runners' `refused` rules.

### B20

`infra_ntp_server_chrony` and `infra_proxy_squid` differ only by a variable

capability over one definition; collapsing them to one role changes each frozen

host. Split on 2026-09-28 from C29, whose function splits are [B47](#b47).
**Exit evidence:** one parameterized managed-service role with its argument
spec, the collection gates over it, and a real-host apply and destroy of one
managed service before the copies are removed.

### B22

### B23

A lifecycle supervisor killed outright (for example by the OOM killer) runs no

their task; run lifecycle playbooks without worker session isolation or make
the invocation a subreaper. X14 delivered the rest of S15. **Exit evidence:** a
killed supervisor leaving no worker.

### B24

in-flight jobs before concurrency rises. X14 delivered the rest of S16. **Exit
evidence:** per-context refusal tests.

### B32

Refusals carry object, reason and remedy. [X31](delivered.md#x31--recovery-setup-custody-refusals-and-adapter-defects) delivered the
per-object reasons `plan` shows, the refusals X19 left to retained output, the
human sudo reason and the controller conflict's key class. What remains: the
stall hint names no node, contrary to the Waiting paragraph of
[container clusters](../container-clusters.md), because the two installer

rendezvous host's registered hosts; refusals made by lifecycle-attempt roles,
such as a physical node's pre-boot identity proof in the managed-OS and cluster

complete", which the `refused` record X31 added could carry; and a JSON
noninteractive sudo refusal still carries no reason and never names SETENV,
because JSON mode discards sudo's lines before the child starts. **Exit
evidence:** diagnostic tests per refusal.

### B49

A real-host apply and destroy, which X4 left as a constraint: no in-tree gate
proves an adapter's real host behavior. The operator runs
[lab-rhel](../../examples/lab-rhel/README.md#run-it) end to end on a clean build
descending from X22's landing commit and records it in the
[acceptance ledger](../../docs/acceptance.md); an owner-accepted row completes
this item. It precedes raising lifecycle concurrency above one ([B17](#b17))
and collapsing the adapter protocol, roles and codecs ([B19](#b19),
[B20](#b20), [B22](#b22)). The same row also meets [B72](m4.md#b72)'s operator
gate when it matches that item's baseline. It also qualifies what X20 proves
only in-tree: the libvirt adapter reading `/proc/1/net` under the elevated
worker's confinement, and `qemu-img info --force-share` against a running
domain's disk; and, run by the owner as a non-root user with cached sudo
credentials, `bootwright status --output json` giving one document and an empty
stderr, then `runtime.privilege` after `sudo -k`. It also qualifies X26's JSON discard of sudo's refresh warning: as a non-root user, `bootwright status --output json < /dev/null` gives one document and an empty stderr with cached credentials, and `runtime.privilege`, exit 1 and an empty stderr under a policy that denies the executable. **Exit evidence:** the
owner-accepted ledger row.

### B175

A host that a build before X30 left with a pending setup receipt whose bundle the store cannot reserve (16 areas held, the receipt's bundle not among them) stays stuck: setup must resume that receipt exactly, the bundle area refuses at the bound, and retirement refuses while a receipt is pending. X30 stops new cases. Recovering existing ones needs a choice between retiring superseded areas under a pending receipt whose bundle holds no reservation and an explicit abandonment path (found in X30). **Exit evidence:** the chosen recovery, with a setup test over a stranded pending receipt.

### B188

Since X29 an active owned managed network whose running definition differs from the frozen request is redefined but never restarted, so the host block stays unproved and the apply does not complete until the network next starts. The choice is between restarting the network under its Machines' quiescence and refusing before the first effect with a named remedy (found in X29). **Exit evidence:** the chosen behavior, with a host replay test over a drifted running network.

### B203

The collection gate names its temporary area with the prefix `bootwright-ansible-check-` and a random part. When that part starts with a digit followed by `if`, `in`, `is`, `or`, `and`, `else`, `for` or `not`, about 0.08% of runs, every ansible-core process prints `SyntaxWarning: invalid decimal literal` and ansible-test fails ansible-doc and validate-modules: the failure X29 saw once (diagnosed in X31). **Exit evidence:** a prefix the random part cannot join into such a token, with a harness test that parses the area path.

### B204

When a context's evidence is unrecognized, the lifecycle's delete exit names `--allow-orphans`, but context deletion refuses unreadable evidence even with that flag, so the remedy is not a runnable exit (found in X31). **Exit evidence:** a refusal test over unrecognized evidence whose named command runs.

### B205

Since X31 an apply is admitted only with entry room for its removal's first pass, but the directory bound still admits an apply at 1023 retained directories and then refuses its removal at registration, and the area's 64 MiB byte bound is not part of admission, so verbose attempts, up to 4 MiB of adapter output each, can fill it and refuse a later record write part way through an operation, a destroy's registration included. Either way the only exit is `context delete --purge --allow-orphans` (found in X31). **Exit evidence:** lifecycle tests at the directory and byte bounds in which the last apply's removal registers and completes.

### B206

The refusal "the context has retained the maximum number of lifecycle operations" names no remedy, and no command prunes retained operations, so deleting the context is the operator's only way out (found in X31). Whether completed operations may be pruned, or the refusal names the deletion, is an owner decision. **Exit evidence:** the chosen remedy, with a refusal golden and its journey test.

### B207

Bundle failures reached from a context's controller stage (tool catalog, projection, transport, metadata, acquisition and trust) still carry setup's remedy, although setup never installs target tools, so rerunning it cannot settle them; the transport failure tells the operator to select a proxy on the controller Machine, which context-free setup never reads instead of naming `HTTPS_PROXY` and `NO_PROXY`; and an unresolved setup receipt's remedy names a context, which setup neither consumes nor records, while the receipt check still compares one (found in X31). **Exit evidence:** remedy tests for the stage, transport and receipt paths.

### B208

The controller spec says a source the retained bundle cannot serve is acquired from its publisher as usual, but the carry-forward refuses whenever the retained bundle cannot read or verify any bootstrap source, so a retained resolution whose bundle lost one leaves every setup refusing (found in X31). Falling back to a fresh resolution or refusing with a remedy is an owner decision. **Exit evidence:** the chosen behavior, with a setup test over a bundle missing a bootstrap source.

### B209

The controller stage re-solves the native libvirt client whenever its roots are missing and retains each new resolution, and nothing retires them, so they can fill the 16-resolution bound; retaining then refuses, and setup at the bound blames client areas and the current bundle (found in X31 by reading the code, not reproduced). **Exit evidence:** a controller-stage test that re-solves past the bound and keeps within it.

### B210

Locating an installed tool reads retained definitions that carry tools, but the store refuses any retained definition with tools and the controller stage retains only the native transaction's, so on a real store the OpenShift install likely always reports its `oc` and `openshift-install` not installed; the install tests pass only because their fake views hold definitions with tools (found in X31 by reading the code, not run on a host). **Exit evidence:** a test over the real contextfs store in which the install locates the tools the controller stage installed.

### B211

Under ansible-core 2.21.4 a failed `no_log` task's message still prints through the `[ERROR]: Task failed:` summary when an assert's message templates a value, a module error names an argument, or a lookup or template error names a value (reproduced in X31), although the security spec makes retained-output secrecy depend on `no_log`; several publish tasks print their refusal only through that summary, and two protocol tests' comments say it is censored. **Exit evidence:** an audit of every `no_log` task that can read bound material, or a censor at the callback, with a test per failure shape.

### B212

The lifecycle and power playbooks import their entry points with `tasks_from: <verb>.yml`, so ansible-core finds no argument-spec entry and never validates a request at run time; only the controller's `main` is validated (found in X31). **Exit evidence:** entry points imported so their specs validate, with a test in which a mismatched request refuses before the first task.

### B213

The libvirt machine's removal observation reads no effect through the presence check, which demands the controller running its frozen image, its system answering, a reported power state and each disk at its frozen size, so a removal resolution over a drifted image, a silent emulated BMC or a resized disk reads partial rather than no effect, as B187 fixed for the host (found in X31). **Exit evidence:** removal-observation rows for each case.

### B214

Since X31 socket claims on SSH hosts are compared per Machine name, so two Machines with the same SSH address and port, or an SSH-addressed Machine that is the controller, are not recognized as one host, and their conflicts fail only at run time (found in X31). **Exit evidence:** a same-host rule with planning refusals for both cases.

### B215

The hypervisor roots leave out libvirt-client, which is selected only when the controller declares the libvirt capability or a Machine is hosted on a libvirt provider, while the host block's presence proof requires it, and on Fedora 43 the daemon does not require the client; so a libvirt provider hosted on the controller with no Machines and no libvirt capability refuses with a remedy that cannot fix it (found in X31, not run on a host). **Exit evidence:** a selection test for that shape.

### B216

The managed-service inspection reads the unit, container and content root but never compares the container's start with its files, so an unknown-outcome resolution of an apply stopped between publishing and restarting may record the block done while the service runs its earlier configuration (found in X31, not verified). **Exit evidence:** an observation test over a container older than its files.

### B217

The installation's observation creates the work area for an identity read and never removes it, and a removal leaves the empty `os/<profile>/` directory the apply created beneath the served root (found in X31). **Exit evidence:** role tests that leave neither behind.

### B218

The agent install turns every substrate target error into "a declared node is on a substrate this executable does not realize" with the remedy to correct the ContainerCluster, so a node refused for an emulated-controller port that does not allocate, or a provider with no emulated-controller credential, gets the wrong reason and remedy (found in X31). **Exit evidence:** refusal-table rows for both.

### B219

If a run's `run.output` lands but its read-back or parent sync then fails, the run directory is not empty, so removing it refuses and an empty output no result names stays behind; the operation area has no way to remove a record (found in X31). **Exit evidence:** an area operation that removes a record, with contract clauses for the store and doubles, and a retain test.

### B220

Since X31 Bootwright reads the cluster through its kept kubeconfig copy, but the installer's own waits still load `auth/kubeconfig`: if a budget kill truncates it and a later apply is not settled, `agent wait-for` fails to load it and the apply stops with the unclassified give-up. Restoring it from the kept copy before a wait writes the installer's state, which needs an owner decision (found in X31). **Exit evidence:** the chosen behavior, with a wait test over a truncated file.

### B221

The controller runner reports that Ansible did not complete when it reads a refused or malformed record after the adapter's failed exit, but reports an unknown outcome when it reads the same record first; X31 made the lifecycle runner order-independent (found in X31). **Exit evidence:** a runner test that forces each order.
