# M1 — Foundations

Deliver substrates, infrastructure services and Machines: realization, OS
installation, shared service lifecycles, identity, access, power, continuation
and safe removal. Contracts: [substrates](../substrates.md), [managed OS](../managed-os.md) and
[infrastructure services](../infrastructure-services.md).

[D158](backlog.md#d158) reopens M1 for the shared work below. Acceptance under [D156](backlog.md#d156) and
[X98](delivered.md#x98--m1-owner-acceptance) stays in the [historical baseline](#accepted-hardening-baseline).

Networking API: [X321 to X324](delivered.md#x321--standalone-network-admission-fixes);
[earlier fixes](#hardening-delivery-history).
Verification tooling: [X446](delivered.md#x446--ci-package-test-budget).
Operator acceptance:
[X444](delivered.md#x444--owner-acceptance-of-validated-operator-gates).

**Requires:** none; each submilestone's Requires names its prerequisites, each arm its declared host and shared contracts. **Exit tier:** in-tree boundary/failure/replay tests and
owner-accepted provider-specific lifecycle runs; M1e requires real hardware
and independent erase proof. M1f/M1g fix their exact qualification profiles
before promotion. **Open decisions:** the item-level definition and
safety gates below, Registry's implementation and the two future adapters.

Audits: [earlier](delivered.md#x304--audit-003-foundation-remediation); 004
[X347 to X373](delivered.md#x347--agent-effect-guard), [X412](delivered.md#x412--server-claims-over-ssh), [X415](delivered.md#x415--single-value-fields-leave-v1alpha1), [X417](delivered.md#x417--observe-host-keys), [X418](delivered.md#x418--truthful-unrealized-state), [X435](delivered.md#x435--preflight-selected-cluster-refusal), [X419](delivered.md#x419--checked-spec-inventories).

### M1a

The existing foundation API review and hardening are part of the accepted
D156 baseline. This maps delivered work, rather than declaring a new audit
complete. Definitions for added provider arms and remaining service/machine
variants stay with their owning items and must close before promotion.

### M1b

The repository, domain ownership, Go/Ansible boundaries and code hardening
accepted under D156 form the structure baseline. The independent M3 work
delivers [B18](delivered.md#b18) and [B23](delivered.md#b23), the shared lifecycle
lock and supervisor safety outcomes. New foundation changes follow the
[architecture contract](../architecture.md); this redefinition starts no
additional refactoring and promotes no parked cleanup. The shared CLI output
presentation (commit 2dc470bff) is recorded under this submilestone in
[X104](delivered.md#x104--owner-answers-of-2026-10-19).

### M1c

Realize libvirt provider hosts and Machines through sushy, install and access
their OS, and prove lifecycle recovery and removal. X98 preserves the accepted
virtual baseline. X47 delivered the shared Redfish trust/access refinements
in-tree; X55 owns machine networking and X60 OS registration, FIPS/access and
root encryption.
[B265](delivered.md#b265) proves machine/network restart exclusion;
[X159](delivered.md#x159--runbook-diagnostics-and-retained-ssh-policy) closes
B509's controller/check-tool procedure under D178. These features also feed
M1e's physical qualification. Ceph service compatibility and cluster
acceptance remain with M2.

[D159](backlog.md#d159) records the session-taken waiver of X55's Requires on
X47's trust contracts and of X60's and B346's Requires on B448, for
implementation only, as the foundation gaps M2c requires; promotion of B74,
B326, B75 to B77 and B346 still requires them. [D168](backlog.md#d168) lets the
session merge a checkpoint-passed, feature-complete slice to local main as soon
as it is done; pushing still waits for the owner. M2c's Ceph slices follow the same rule; its current implementation and
remaining gates are recorded in [M2c](m2.md#m2c).

X60's in-tree work is implemented on main: the
FIPS install arm ([B75](#b75)), the registration arm with the
`spec.subscription` lift, `destroy --unregistered` and the pre-stop removal
phase ([B76](#b76)), root-disk encryption (B77, accepted in
[X246](delivered.md#x246--bounded-managed-os-operator-acceptance)) and FIPS controller
access ([B346](#b346)). Each lane commit records its in-tree gates, and the
full gates (`make check`'s steps, `make race`, `make vulncheck` and every
Ansible suite) passed at X60's integration checkpoints and on the offered
branch; the one failure there was the known load flake [B673](delivered.md#x247--setup-lease-release),
which passed when rerun. B75, B76 and B346 retain their remaining operator
gates.
[B448](delivered.md#x47--pre-effect-ssh-key-policy)'s shared pre-effect key-policy refusal is implemented, including
its empty pinned-key diagnostic; it no longer blocks their in-tree delivery.
Their remaining live rows stay the owner's. Their registered
**Acceptance baseline** is `d129085a1835bd09618b79ac3d1342085b631709`,
the X60 integration record on main. X60's remaining virtual-host operator
gates stay with B75, B76 and B346. [B78](#b78) extends the shared implementation and
qualification to physical hosts.

[D172](backlog.md#d172) schedules B700 with M3b and B701 to B703 with M3d
(D158).

### M1d

Own shared infrastructure-service lifecycle delivery. The accepted artifact,
proxy, DNS and time-service baseline is preserved; [X360](delivered.md#x360--a-managed-registry-on-its-placement-machine)
delivered B68's managed Registry. The managed LoadBalancer candidate [B100](backlog.md#b100)
remains parked, with no consumer; this regrouping does not promote it.
Cluster-specific registry use remains in M3's B69. Hostname listener inspection
is delivered in [X437](delivered.md#x437--hostname-listener-firewall-inspection).

### M1e

Realize and install physical Machines through their BMCs, qualify trust,
identity, private publication, access and networking, and prove interruption,
reboot and removal. X62 retains its existing implementation and pending
operator gates; X63 owns independent physical erase safety; X100 qualifies
the supported managed-host matrix; X190 applies or proves declared physical
firmware. Existing retaining removal is not erase.
M2d and M3 consume this foundation and keep their full-cluster acceptance.

### M1f

Deliver the vSphere substrate and its Machine lifecycle through [B99](#b99),
on the media and power port of [B704](delivered.md#b704). [M3f](m3.md#m3f) owns OpenShift
clusters on these Machines and records the cluster-facing requirements in B99's
detail. Adapter, installation, identity, trust, ownership, recovery/removal and
executable qualification need definition. It does not gate libvirt or
bare-metal consumers.

### M1g

Deliver the OpenShift Virtualization substrate through [B87](#b87)'s KubeVirt
arm, using an existing qualified host cluster, on the media and power port of
[B704](delivered.md#b704), which is scheduled with M3e (D158) and serves every arm.
[M3e](m3.md#m3e) owns provisioning OpenShift clusters on these Machines and
requires this arm; M1g does not require M3e or a Bootwright-built host.

### Controller setup v2

**Why.** The owner's request of 2026-10-14 (D152): setup took more than three
minutes even after an earlier build's setup, and Fedora 43 to 44 broke it.
Today setup resolves and installs a private CPython, ansible-core and a frozen
controller DNF plan into a per-build bundle area of about 190 MB, guarded by
byte digests of glibc and libgcc, so any build or OS update repeats most of it.

**Design.** Setup installs two things, and only when they are missing.
Host packages are asked of the host's own dnf by name or RPM capability, with
a verbatim `--assumeno` preview shown before confirmation. One venv on the OS
CPython 3.12 to 3.14 (`/usr/bin/python3.X`) receives the wheels of a hash lock
each build embeds, installed by pip with `--no-index --no-deps
--require-hashes` from a content-addressed wheel cache. The automation stays in
the binary and is unpacked into root-owned staging for each Ansible launch, so
the runtime's identity is the lock digest, the Python ABI and the interpreter
path, and a live operation's closure is the lock digest and the ABI: an
`ansible/`-only fix or any rebuild with the same lock needs no setup and
continues a live operation. Setup state moves to a setup-owned subtree,
`/var/lib/bootwright/setup/` (state, lock, runtimes, wheel cache, run logs),
whose format heals itself. The cut-over bumps the registry to version 6 and the
controller record to version 3 and refuses an earlier store with the
fresh-install remedy. D152's clauses hold every choice and what was declined.

**Targets** (the owner measures before in X87's S0 and after in X90's
acceptance): a fresh setup within 60 s excluding dnf, the ready path within
2 s, a new build with the same lock within 2 s, and a runtime of at most 60 MB
and 3,000 files.

**Plan.** Each step is one gate-passing commit; each slice is squashed to one
commit on local main.

- **X87, foundations,** is
  [delivered](delivered.md#x87--controller-setup-v2-foundations): additive
  and unwired, so behavior is unchanged except B548. B549 and B552 remained open
  for X90. **S0, not measured:** on 2026-10-14 the old build `5345d2f95` and
  X87's `890ba11c7` both refused `setup` on the owner's Fedora 44 host with
  `controller.setup` ("bootstrap publisher returned an unapproved
  response") in under a second, because all eight retained definitions were
  Fedora 43, so neither a ready path nor a new-build path existed to time.
  The bundle area held 1,920,036,538 bytes in 43,729 files (Python 3.14.7,
  ansible-core 2.21.4).
- **X88, the cut-over,** is
  [delivered](delivered.md#x88--controller-setup-v2-cut-over) on main after
  the owner deferred D152's clause 9 choice on 2026-10-14; D154 chose its
  option (b).
  Before any X88 build runs on the owner's host, the owner retires the live
  contexts with the old build and removes both store roots.
