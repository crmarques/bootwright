# M1 — Hardening

Security, code and architecture improvement, and bug fixes. M1 holds the
pre-OpenShift readiness program the owner started on 2026-09-26, the 2026-09
audit follow-ups, the owner's full bar of 2026-10-05, and the safety, recovery
and operability items that serve no single product milestone. The
[product scope](../project.md#product-scope) names no platform for it; it
serves the [design priorities](../project.md#design-priorities-and-non-goals)
of least privilege and fail-closed effects.

**Requires:** none. **Exit tier:** in-tree, plus the real-host run of
[B49](delivered.md#x38--the-real-host-run-of-2026-10-05) and the extended
lab-rhel run D59 sets on a clean build of X44's landing. **Open decisions:**
none; D117 and D118 settled the last two on 2026-10-06. **Scope:** the owner's full
bar (D56, which amends D48): well-defined specs, architecture and code that
follow best practices, domain-constrained APIs with input validation, clear
CLI output, and a CLI ready for every controller function and for RHEL
machines on libvirt and sushy-tools. It holds what the 2026-10-05 audit found
in M1's journeys, the parked items D56 attached and the items B278 to B302 and
B336 to B338 it added. Since D116, which amends D56 and D48, a safety or
defect follow-up that a slice from X39 on finds in M1's journeys joins M1 on
X46, the sweep slice before the closing run, or on an earlier planned slice
whose lane already owns its files, as ten of X39's did; any other follow-up
stays parked in the [backlog](backlog.md) under D48. The real-hardware test
follows M1 (D60).

### B339

Under sudo's `use_pty`, its default since 1.9.14, an interactive invocation
hands sudo the terminal and sudo runs the elevated child in the foreground of
a pseudo-terminal of its own, so a second Ctrl-C reaches only the child, which
finishes its bounded cancellation instead of being killed: the supervisor,
which kills sudo on a second signal it receives, never sees it (found in X39,
which narrowed the operator guide and the CLI spec to say so). The child would
escalate on its own second signal only when it proves it is the foreground
process group of a pseudo-terminal other than the supervisor's terminal, where
each Ctrl-C reaches it once, never without a pty or in a background pty, where
sudo hands it one interrupt twice. **Exit evidence:** a real-sudo run on
Fedora 43 (`use_pty`) and on RHEL 9.8 in which a second Ctrl-C ends the
command at once and a single Ctrl-C never does.

### B340

Bounded runs, the `machine` power commands and the power read of

the authored strings their requests carry, such as BMC endpoint values, and the

request, before its runtime is lent, would name such a value. **Exit
evidence:** a power command and a power read whose request holds a delimiter

field.

### B342

An InfraProvider's `networkAttachments[].libvirt.bridge` admits any non-empty
string and is rendered unescaped into an XML attribute of the libvirt network
and domain definitions, and a Machine's
`spec.network.interfaceAttachments[].interface` has no interface-name rule and
no row in the machines spec's network table (found in X39). Both take the
Linux interface-name rule X39 added, and the two templates escape the
attribute, which moves the automation digest.
[X42](delivered.md#x42--media-contexts-setup-service-and-machine-admission)
delivered the admission half without moving it: both fields took the `ifname`
grammar, and the machines spec's tables state it; X43 narrowed the bridge to a
`bridge` grammar that refuses a trailing `+` (B410). The templates' half remains,
for X46's digest window: the libvirt network and domain templates escape the
bridge attribute, and the request-template test's libvirt bridge case, which
skips since admission refuses its value first, again exercises the
planning-time template refusal. **Exit evidence:** template goldens escaping
the attribute, and that case running.

### B357

Since X40 a trust write that takes over an endpoint removes the record of a
Machine the context no longer declares (D65), but not that of a Machine it
still declares that no longer uses its SSH trust: one reached locally,
installed by Bootwright, declaring no SSH access or declaring a
`knownHostsRef`. Nothing reads such a record, yet it blocks trusting another
Machine at that endpoint. The refusal's only remedy is to leave that Machine
out of the input for one `context update`, which refuses under an incomplete
operation, cannot drop a Machine another object references, and leaves the
next apply refusing the changed input until a destroy; the controller
Machine's record has no exit once an apply has bound the context. That
controller remedy also no longer says that no other object may reference the
controller Machine, and the CLI spec says the input then compiles, which is
false for every tracked example (found in X40). The alternatives: widen D65 so
the confirmed write also drops an exempt Machine's record, shown as a `remove`
row (recommended); add a confirmed way to forget one exempt Machine's record;
or keep the input-edit remedy and restore the controller's precondition.
**Exit evidence:** the owner's decision; under the recommendation,
`machine trust` and a first use over an exempt Machine's record, the
controller's included, writing a `remove` row in every lifecycle state with no
input edit, otherwise the controller remedy and the CLI spec naming every
reference to move; and `make quick`, `make docs-check`, `make check`,
`make race` and an independent review of the diff.

Decided on 2026-10-06 (D117): D65 widens. A confirmed trust write that takes
