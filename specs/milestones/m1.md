# M1 — Hardening

Security, code and architecture improvement, and bug fixes. M1 holds the
pre-OpenShift readiness program the owner started on 2026-09-26, the 2026-09
audit follow-ups, the owner's full bar of 2026-10-05, and the safety, recovery
and operability items that serve no single product milestone. The
[product scope](../project.md#product-scope) names no platform for it; it
serves the [design priorities](../project.md#design-priorities-and-non-goals)
of least privilege and fail-closed effects.

**Requires:** none. **Exit tier:** in-tree, plus the real-host run of
[B49](delivered.md#x38--the-real-host-run-of-2026-10-05) and the extended
lab-rhel run D59 sets on a clean build of X44's landing. **Open decisions:**
whether a trust write also drops the record of a Machine the context still
declares but no longer trusts by SSH ([B357](#b357)), and whether a file-input
secret replacement, deletion or rotation confirms before the lease
([B372](#b372)); D56 to D116 settled every other. **Scope:** the owner's full
bar (D56, which amends D48): well-defined specs, architecture and code that
follow best practices, domain-constrained APIs with input validation, clear
CLI output, and a CLI ready for every controller function and for RHEL
machines on libvirt and sushy-tools. It holds what the 2026-10-05 audit found
in M1's journeys, the parked items D56 attached and the items B278 to B302 and
B336 to B338 it added. Since D116, which amends D56 and D48, a safety or
defect follow-up that a slice from X39 on finds in M1's journeys joins M1 on
X46, the sweep slice before the closing run, or on an earlier planned slice
whose lane already owns its files, as ten of X39's did; any other follow-up
stays parked in the [backlog](backlog.md) under D48. The real-hardware test
follows M1 (D60).

## Item detail

### B290

`media add` and `media list --checksums` run silent for minutes to hours;
acquisition failures name the wrong cause, a dead redirect message included,
and never show the deadline, the TLS or DNS failure or the HTTP status; the
reserved-image refusal gives impossible advice and names no context; an
over-long origin is refused only after the download, and a signed URL's query
is recorded; `media list --checksums` hides the computed digest, and one short
image fails the whole list; plain-HTTP media URLs contradict the
TLS-verified, HTTPS-only rules; and media confirmations and refusals omit the
image's identity (found by the 2026-10-05 audit). Media URLs are HTTPS only
(D86). **Exit evidence:** progress goldens for `add` and `list --checksums`,
with JSON staying silent; redirect, DNS, certificate, timeout and HTTP 404
failures each naming their own cause, and the deadline named; the
reserved-image refusal naming the reserving context and
`bootwright destroy --context <it>`; over-long or control-character origins
refused before any download, and a query-bearing URL recorded without its
query; `http://` refused; `list --checksums` reporting the computed digest,
separating reserved from verified and marking a short entry failed; the media
JSON rows documented; and `make quick`, `make docs-check`, `make check`,
`make race` and an independent review of the diff.

### B236

A context whose evidence is corrupt or unsupported still has no runnable exit:
deletion refuses it even with `--allow-orphans`, and the only remedy named is
a whole-store restore no procedure provides. The lost-binding refusal and its
status step still name the orphan-acknowledged delete whatever the evidence
reads; the context guard's evidence refusal names no remedy; and the lifecycle
compares evidence by exact bytes where the guard accepts any spelling (found
in X32). `--allow-orphans` may abandon such a context, saying that its objects
cannot be listed, and the refusal names that exit (D89). **Exit evidence:**
that exit, the guard's unreadable-evidence refusal naming it, and each refusal
naming a delete the guard admits; and `make quick`, `make docs-check`,
`make check`, `make race` and an independent review of the diff.
