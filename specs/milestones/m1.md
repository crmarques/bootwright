# M1 — Hardening

Security, code and architecture improvement, and bug fixes. M1 holds the
pre-OpenShift readiness program the owner started on 2026-09-26, the 2026-09
audit follow-ups, the owner's full bar of 2026-10-05, and the safety, recovery
and operability items that serve no single product milestone. The
[product scope](../project.md#product-scope) names no platform for it; it
serves the [design priorities](../project.md#design-priorities-and-non-goals)
of least privilege and fail-closed effects.

**Requires:** none. **Exit tier:** in-tree, plus the real-host run of
[B49](delivered.md#x38--the-real-host-run-of-2026-10-05) and the extended
lab-rhel run D59 sets, including D125's three-node concurrency evidence, on a
clean build of `main` at or after the commit that delivered X44 and X48 to X51
under D139, which contains X44, X46's second pass and X48 to X51.
**Open decisions:** none, except that [B470](#b470)'s deferral stands (D126,
D139) and D140, the stop-at-payload rule for `machine exec` and `cluster exec`,
was taken by the session and awaits the owner's review. D127 fixed B466's
publication contract, and D117 and D118 settled the earlier two on 2026-10-06.
**Scope:** the owner's full bar (D56, which amends D48): well-defined specs,
architecture and code that
follow best practices, domain-constrained APIs with input validation, clear
CLI output, and a CLI ready for every controller function and for RHEL
machines on libvirt and sushy-tools. It holds what the 2026-10-05 audit found
in M1's journeys, the parked items D56 attached and the items B278 to B302 and
B336 to B338 it added. Since D116, which amends D56 and D48, a safety or
defect follow-up that a slice from X39 on finds in M1's journeys joins M1 on
X46, the sweep slice before the closing run, or on an earlier planned slice
whose lane already owns its files, as ten of X39's did; any other follow-up
stays parked in the [backlog](backlog.md) under D48. The real-hardware test
follows M1 (D60).

### B339

Under sudo's `use_pty`, its default since 1.9.14, an interactive invocation
hands sudo the terminal and sudo runs the elevated child in the foreground of
a pseudo-terminal of its own, so a second Ctrl-C reaches only the child
(found in X39). [X46](delivered.md#x46--the-safety-and-defect-sweep-of-m1) delivered the in-tree
proof: the child exits at once with status 130 on its own second signal only
where it proves it is the foreground process group of a pseudo-terminal other
than the supervisor's terminal, never without a pty or in a background pty,
where sudo hands it one interrupt twice. **Remaining:** a real-sudo run on
Fedora 43 (`use_pty`) and on RHEL 9.8 in which a second Ctrl-C ends the
command at once and a single Ctrl-C never does, which D59's closing run
carries and which also confirms the operator's terminal is left sane, since
the exit skips the child's deferred cleanup; the owner-accepted ledger row
completes the item.

### B276

The [lab-rhel](../../examples/lab-rhel/README.md) README checked the managed time service with `chronyd -Q -t 3`, which timed out on 2026-10-05 against a managed server that had selected its upstream source 36 seconds earlier. The timeout bounds the whole query, and that server itself took four seconds from its start to selecting its source with `iburst` (10:44:44 to 10:44:48 UTC, and 10:59:40 to 10:59:44 UTC for the next instance), so three seconds is shorter than chrony needs to select a source (found in B49's run). Probes the recording session made at 11:02 UTC, outside the run's records, saw the same timeout and an offset with `-t 10`.

[X44](delivered.md#x44--help-completion-contracts-and-ratchets) delivered the
in-tree half: the README's check moves to `-t 10`, says that a printed offset
is success, and lists chrony, bind-utils and qemu-img among the prerequisites.
**Remaining:** the check run on a host against a synchronized managed server,
in D59's owner-accepted closing run; the owner-accepted ledger row completes
the item.

### B466

**Implementation:** delivered in-tree by
[X48](delivered.md#x48--bounded-concurrent-execution) under D127; only D125's
concurrent operator gate remains.

The DAG already admitted independent infrastructure services and libvirt
machines, and the scheduler already implemented bounded concurrent execution.
Before X48, production nevertheless passed `Concurrency: 1` in
`cmd/bootwright/wiring_reconciliation.go`, and
`TestLifecycleConcurrencyBound` enforced it pending B303 and B304. A second,
independent limit was in `internal/managedos/installation/requests.go`:
`Request.ExclusiveKeys` froze the shared package-tree path on each entire
installation block, holding it through installer boot and completion.
Same-profile installations therefore serialized even with a higher production
bound. Wave width measures graph shape; it neither overrides the bound nor
accounts for exclusive resources.

Authorized on M1 by D127 after rebasing over main. The shared publication
realizes `MachineInstallProfile` under implementation/request
`os-package-tree-v1`, with evidence `os-package-tree-evidence-v1`;
installation requests advance to `os-install-anaconda-v8`.
[Managed OS](../managed-os.md#shared-package-tree-publication) owns
partial-effect, interrupted-removal, replay and old-plan contracts.

**What X48 delivered, and where each step is proved:**

1. B303 and B304 precede the bound: every role receives the runner's private
   scratch, durable machine work and libvirt provider media occupy disjoint
   `machines` and `providers` namespaces, and an invocation's own live jobs
   pass the running-adapter refusal while a foreign, unattributed or orphaned
   job still refuses. The runner's scope tests in
   `internal/reconciliation/ansiblerunner`, the role scratch and remnants unit
   tests, and the structural no-fixed-scratch rule with its self-tests prove it.
2. Managed OS owns one durable package-tree publication block per context and
   install profile with a hosted tree, in the `machines` stage; each
   installation requires it and holds no exclusive tree claim.
   `TestThreeInstallationsHaveOneSharedPublication` and the production-DAG test
   in step 5 prove one publication block with one exclusive key, which each
   installation requires and none holds.
3. Tree extraction, atomic publication, observation and removal moved to that
   owner, with its own evidence; inverse dependencies retain the tree until
   every consumer is removed. `TestTreeRequestAndEvidenceGoldens`,
   `TestTreeContinuationClassifiesPartialAndInterruptedRemoval`,
   `TestTreeOldRequestAndEvidenceVersionsRefuse`,
   `TestATreeApplyNamesItsRefusalsWithTheirRemedy` and the role harness in
   `test_managedos_package_tree.py` prove replay, continuation after partial
   publication, interrupted removal and the named refusals.
4. Production uses the engine's bound of eight with no public flag or
   desired-state field; `TestLifecycleConcurrencyBound` enforces it.
5. Production composition is qualified at three levels.
   `TestTheComposedInvocationScopeAdmitsSiblingRunsOfItsRunner` takes the
   composed options' invocation scope with a real runner and a controlled
   adapter, proves that two sibling runs are admitted while a run outside the
   scope refuses, and fails when the scope is unwired.
   `TestThreeNodeRHELExampleSharesOnePublicationAndAdmitsIndependentWork`
   compiles the three-node example through the production capabilities and
   checks which blocks are ready together, exclusive keys, selected stages and
   the inverse order.
   `TestThreeMachineWavesRunInOneInvocationWithPrivateScratch` runs each wave
   of a three-Machine apply and destroy through real adapter processes held at
   barriers. The cancellation case is
   `TestInvocationScopeClosesOnlyAfterEveryCanceledAdapterSettles`. The full
   lifecycle composition over the example with the real runner and controlled
   adapters is parked as [B495](backlog.md#b495), because D125's operator gate
   proves overlap on a host.

**Remaining exit evidence:** D59's owner-accepted closing run on a clean build
of `main` at or after the delivery of X44 and X48 to X51. The operator gate uses
a repository fixture with independent managed services and at least three
libvirt Machines sharing an install profile, proves overlapping service and
machine work, one shared-tree publication, overlapping installation waits,
repeated apply and safe destroy with no sibling scratch or units left behind.
Earlier serial acceptance does not meet this gate. The item and M1 remain
incomplete until the concurrent operator gate passes.
