# M1 — Hardening

Security, code and architecture improvement, and bug fixes. M1 holds the
pre-OpenShift readiness program the owner started on 2026-09-26, the 2026-09
audit follow-ups, the owner's full bar of 2026-10-05, and the safety, recovery
and operability items that serve no single product milestone. The
[product scope](../project.md#product-scope) names no platform for it; it
serves the [design priorities](../project.md#design-priorities-and-non-goals)
of least privilege and fail-closed effects.

**Requires:** none. **Exit tier:** in-tree, plus the real-host run of
[B49](delivered.md#x38--the-real-host-run-of-2026-10-05) and the extended
lab-rhel run D59 sets on a clean build of X44's landing. **Open decisions:**
[B466](#b466)'s shared-publication request and evidence versions, effect and
continuation contract; D117 and D118 settled the earlier two on 2026-10-06.
**Scope:** the owner's full bar (D56, which amends D48): well-defined specs,
architecture and code that
follow best practices, domain-constrained APIs with input validation, clear
CLI output, and a CLI ready for every controller function and for RHEL
machines on libvirt and sushy-tools. It holds what the 2026-10-05 audit found
in M1's journeys, the parked items D56 attached and the items B278 to B302 and
B336 to B338 it added. Since D116, which amends D56 and D48, a safety or
defect follow-up that a slice from X39 on finds in M1's journeys joins M1 on
X46, the sweep slice before the closing run, or on an earlier planned slice
whose lane already owns its files, as ten of X39's did; any other follow-up
stays parked in the [backlog](backlog.md) under D48. The real-hardware test
follows M1 (D60).

scratch and adapter-admission prerequisites, [B303](#b303) and [B304](#b304),
return from M3, and [B466](#b466) gives shared package-tree publication its own

### B339

Under sudo's `use_pty`, its default since 1.9.14, an interactive invocation
hands sudo the terminal and sudo runs the elevated child in the foreground of
a pseudo-terminal of its own, so a second Ctrl-C reaches only the child
(found in X39). [X46](delivered.md#x46--the-safety-and-defect-sweep-of-m1) delivered the in-tree
proof: the child exits at once with status 130 on its own second signal only
where it proves it is the foreground process group of a pseudo-terminal other
than the supervisor's terminal, never without a pty or in a background pty,
where sudo hands it one interrupt twice. **Remaining:** a real-sudo run on
Fedora 43 (`use_pty`) and on RHEL 9.8 in which a second Ctrl-C ends the
command at once and a single Ctrl-C never does, which D59's closing run
carries and which also confirms the operator's terminal is left sane, since
the exit skips the child's deferred cleanup; the owner-accepted ledger row
completes the item.

### B466

The DAG already admits independent infrastructure services and libvirt
machines, and the scheduler already implements bounded concurrent execution.
Production nevertheless passes `Concurrency: 1` in
`cmd/bootwright/wiring_reconciliation.go`, and
`TestLifecycleConcurrencyBound` enforces it until [B303](#b303) and
[B304](#b304) close. A second, independent limit remains in
`internal/managedos/installation/requests.go`: `Request.ExclusiveKeys` freezes
the shared package-tree path on each entire installation block, holding it
through installer boot and completion. Same-profile installations therefore
serialize even with a higher production bound. Wave width measures graph
shape; it neither overrides the bound nor accounts for exclusive resources.

Planned after X46 and deferred until B303 and B304 close. Before promotion,
fix the shared publication's capability identity and request/evidence
versions, its partial-effect and interrupted-removal classifications, and
the exact replay and old-plan refusal contracts in the owning specs. These
are definition work within X48, not a reason to defer the outcome beyond M1.

**Implementation plan, in order:**

1. Complete B303 and B304, auditing shared mutable files and short host
   effects such as unit publication and daemon reload. Keep disjoint domains,
   BMCs, media downloads and units independent. Qualify interleaved native
   effects and add a narrow resource boundary only for a proved conflict;
   avoid a host-wide claim held through an entire service or installation.
2. Give Managed OS one durable package-tree publication block per context and
   install profile with a hosted tree, in the `machines` stage. It realizes
   the `MachineInstallProfile` publication; each installation requires it in
   domain terms, alongside its own Machine realization and referenced
   services. Project only shared tree placement, source media pin, path,
   serving trust and profile identity into its frozen request. Refuse
   conflicting source pins for one publication path. Acquire that path's
   exclusive claim only on the publication block; completed publication is
   immutable while its consumers run. Machine installers read it and retain
   their own image, private material, boot and completion evidence.
3. Move tree extraction, atomic publication, staging cleanup, observation and
   removal into that owner. Its evidence proves the frozen source and the
   complete marker, or reports partial/no effect; machine evidence checks the
   dependency without counting the tree alone as its own installation effect.
   Inverse dependencies retain the tree until every installation consumer is
   removed, then remove it before its artifact server. Qualify replay and
   continuation after partial publication, a failed or unstarted consumer,
   and interrupted removal. Update the owning specs and version frozen
   requests, evidence and automation when their contracts change; document
   the resulting old-build removal requirement before a host upgrade.
4. Remove production's serial override and use the engine's existing
   `MaxRunningBlocks = 8`. Update the composition test to enforce that bound;
   retain serial fixture bounds only where a test needs them. Keep the bound
   an executable property with no public flag or desired-state field. Reuse
   the scheduler: dependency readiness, stage selection, exclusive resources,
   observation precedence, isolated retry, cancellation and failure drainage
   remain its admission rules.
5. Qualify production composition through the real runner with controlled
   adapters: infrastructure siblings overlap, libvirt machines overlap and
   three installations sharing one profile overlap after one publication.
   A fast chain advances while an unrelated slow block remains running;
   selected stages still pause and resume. Record actual overlap from held
   barriers or timestamped starts/finishes, rather than only wave counts or
   elapsed-time improvements. Preserve readable concurrent progress and
   plan-order diagnostics, and include failure, required-log failure,
   cancellation, unknown resolution, replay and inverse-DAG cases.

**Exit evidence:** the preceding contract tests and independent safety review;
collection unit and lint gates, `make quick`, `make docs-check`, `make check`
and `make race`; and D59's owner-accepted closing run on a clean build after
