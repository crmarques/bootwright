# M1 — Hardening

Security, code and architecture improvement, and bug fixes. M1 holds the
pre-OpenShift readiness program the owner started on 2026-09-26, the 2026-09
audit follow-ups, the owner's full bar of 2026-10-05, and the safety, recovery
and operability items that serve no single product milestone. The
[product scope](../project.md#product-scope) names no platform for it; it
serves the [design priorities](../project.md#design-priorities-and-non-goals)
of least privilege and fail-closed effects.

**Requires:** none. **Exit tier:** in-tree, plus the real-host run of
[B49](delivered.md#x38--the-real-host-run-of-2026-10-05) and the extended
lab-rhel run D59 sets on a clean build of X44's landing. **Open decisions:**
none; D56 to D115 settled the last on 2026-10-05. **Scope:** the owner's full
bar (D56, which amends D48): well-defined specs, architecture and code that
follow best practices, domain-constrained APIs with input validation, clear
CLI output, and a CLI ready for every controller function and for RHEL
machines on libvirt and sushy-tools. It holds what the 2026-10-05 audit found
in M1's journeys, the parked items D56 attached and the items B278 to B302 and
B336 to B338 it added. What later slices find is parked in the
[backlog](backlog.md) unless the owner attaches it (D48), and the
real-hardware test follows M1 (D60).

## Item detail

### B244

ansible-core 2.21.4 loads a runner's `--extra-vars @request.json` as trusted
templates, so a request string holding Jinja delimiters is rendered on the
controller, and since X32 argument validation renders every declared request
string before the first task; no Go check refuses such delimiters. The install
request would also carry `endpoints: null` if no endpoint address resolved,
which validation now refuses (found in X32). The 2026-10-05 audit reproduced
it: authored desired-state strings reach such requests, so an authored value
can run code as root on the controller. Both runners pass every request string
as unsafe data, which leaves the frozen request bytes and every digest
unchanged, and planning refuses before registration any block whose canonical
request holds `{{`, `{%` or `{#`, naming its object and field. **Exit
evidence:** in both runners, request strings holding `{{ 7*6 }}` or a
`lookup('pipe', 'id')` expression reach the module argument verbatim under the
pinned ansible-core 2.21, in the collection's units suite; a planning refusal
for each proven path (packages, `noProxy`, the proxy URL path, listener and
endpoint names, the bridge), the controller prerequisites included; and
`make quick`, the collection's units and lint suites, `make docs-check`,
`make check`, `make race` and an independent review of the diff.

### B279

Authored strings that reach native configuration have no grammar of their own:
service, package, `baseURL`, interface-name and next-hop values can inject
Kickstart directives or root `%post` code; `spec.libvirt.uri` is unconstrained
and written into the emulated BMC's Python configuration; a bare-metal
`hostKeyRef` may name the fleet or a cluster SSH key; a generated username or
comment admits NUL, which generation refuses; and the machines spec calls
blank lines in `knownHostsRef` material invalid while the parser accepts blank
and comment lines (found by the 2026-10-05 audit). Admission gives each value
a grammar, the Kickstart renderer refuses what slips through, and
`spec.libvirt.uri` is an enumeration holding `qemu:///system` (D61). Valid
inputs render the same bytes, so no request digest moves. **Exit evidence:**
lexical rows in which an HTTP(S) URL refuses whitespace, non-printable runes
and the characters RFC 3986 excludes, and `baseURL` refuses a fragment or a
quote; admission refusals for a service name holding a newline, a package
entry starting with `%` or `-`, an NMState interface name over 15 bytes or
holding `/`, and a next hop that is not an IP; the renderer refusing a control
character in any interpolated value and whitespace or a leading `%` in a
single-token value; a libvirt URI other than `qemu:///system` refused; a
`hostKeyRef` equal to the fleet key, an access `privateKeyRef` or a cluster
SSH key refused naming both objects; a generated username or comment holding
NUL refused at validate; the machines spec saying blank and comment lines are
ignored; and `make quick`, `make docs-check`, `make check`, `make race` and an
independent review of the diff.

### B282

The elevated child opens every operator-named path as root, the input
directory, the Context file, a media source, secret files and `--ssh-id-file`
among them, contrary to the CLI spec: on a root-squashed network home those
files can never be read, and every refusal blames the file; and
`media add --from-file` follows symlinks, blocks on a FIFO and never checks
that the invoking account may read the file (found by the 2026-10-05 audit). A
bounded helper under the invoking credentials opens each operator-named path
with the existing no-follow rules and passes the descriptors to root, which
keeps every proof (D111). **Exit evidence:** an injectable opener proving that
the root child opens no operator path; the helper's descriptors re-proved by
root for type, stability and ownership; `EACCES` or `EPERM` on each path
refused naming it, saying that root cannot read it and giving the local-copy
remedy; `--from-file` refusing a FIFO, a final-component symlink, a device and
a file the invoking account cannot read; `validate -f` and `context init`
agreeing on one directory; and `make quick`, `make docs-check`, `make check`,
`make race` and an independent review of the diff.

### B283
