# M3 — Full OpenShift cluster provisioning

Fully provision, verify, continue and destroy OpenShift clusters on physical
bare metal through BMCs and on libvirt guests behind sushy-tools Redfish BMCs.
[B473](#b473) defines the complete cluster provisioning coverage; single-node
installation alone does not complete this milestone. The
[product scope](../project.md#product-scope) names bare metal through BMCs and
OpenShift container clusters. The day-2 surface a completed cluster exposes is
a [non-goal](../project.md#design-priorities-and-non-goals) and stays parked
as [B106](backlog.md#b106). Every expansion beyond B61's topology destroys a
completed [legacy M1e](delivered.md#m1e--lifecycle-engine-and-managed-artifact-serving) snapshot before a fresh expanded apply.

**Requires:** M2 and the applicable [M1c](m1.md#m1c), [M1d](m1.md#m1d)
and [M1e](m1.md#m1e) foundations. M1 owns shared BMC, managed-host and
physical removal qualification; this milestone keeps full-cluster acceptance.
M1f/M1g do not gate these provider paths. B18, B23 and B265 remain M3
completion gates after moving to M1; this does not reopen B61 or make them
prerequisites for every implementation slice. The items need M1's B1, B3, B5 and B6
beside the trust and custody [X21](delivered.md#x21--bmc-trust-and-administrator-custody) delivered; and
B72, which [X38](delivered.md#x38--the-real-host-run-of-2026-10-05)
completed after B61's waiver. **Exit tier:** full-cluster emulated rehearsal on
libvirt+sushy and real hardware through BMCs, with owner-accepted ledger rows
covering B473's complete feature matrix, continuation and safe destroy
(D17, D128). **Open decisions:** exact release and
installation feature coverage (B473), and whether additional trust bundles
feed the cluster-wide trusted CA ([B195](#b195)).

X14 to X16 delivered the cluster hardening that made B61's operator gate
runnable, under their own IDs in [delivered](delivered.md).

## Planned slices

None yet: B61 awaits its operator gate, and B473 fixes complete cluster
coverage before the remaining implementation slices are planned.

## Item detail

### B61

**Owners:** Container cluster and Substrate, with Infrastructure services,
Controller, Secrets and State reconciliation; using Machine. **Requires:**
B72, waived on explicit request on 2026-09-16 and completed by
[X38](delivered.md#x38--the-real-host-run-of-2026-10-05). **Acceptance
baseline:** `8aa4494`, where X11 landed. The agent-installer part of M3,
without [B52](m7.md#b52)'s `render installer`, [B59](m7.md#b59) or
[B70](m1.md#b70).

**Deviation.** A physical cluster node refuses before registration:
[X20](delivered.md#x20--substrate-port-pre-boot-proof-and-observations) delivered the pre-boot target proof and its pin
comparison, and [B67](#b67) lifts the refusal. From 2026-09-26 the operator gate could not pass, because the install
identity came from a `metadata.json` the agent installer never writes and the
served image was unreadable by the artifact server; X14 to X16 repaired both,
so the gate can run again.

**Descoped:** the administrator-access custody contract moved to B10,
which [X21](delivered.md#x21--bmc-trust-and-administrator-custody) delivered.

**Supported shape.** Nodes that are virtual Machines on a realized substrate;
single-node is the rehearsed topology and multi-node libvirt stays admitted
(D9) under the topology checks X16 delivered. The rest is
[selection and refusal](../container-clusters.md#selection-and-refusal): a
release declared by version, the `agent` method, `connected` mode. OKD,
disconnected mode, FIPS, disk encryption, serving certificates, registry policy
and a release pinned by image alone refuse. Consumer:
[`examples/container-clusters/lab-sno`](../../examples/container-clusters/lab-sno/README.md).

**Capabilities.** [Boot media](../container-clusters.md#boot-media) proves the
installer against the release and builds the agent image from the
[projected inputs](../container-clusters.md#installer-inputs), published
privately because it carries the pull secret.
[Installation](../container-clusters.md#installation) boots each node through
its [substrate's boot operation](../substrates.md#identity-and-power-operations)
and reads the cluster back before releasing the media.

**Exit evidence:** the `containercluster` projection suite (install-config and
agent-config goldens for a single-node libvirt cluster, a multi-node libvirt
cluster and a multi-node physical cluster, the derived platform and rendezvous
address, and the refusals above); the capability suite for both blocks (the
installer-version refusal, private publication removed by the inverse, the
resumable and terminal wait classifications, completion proved against the
cluster's own identity, replay without a rebuild, an inverse that retains the
cluster, quiescence); the substrate boot-operation tests for both arms; the
managed resolver's cluster records; the `examples/container-clusters/lab-sno` acceptance; and
`make check`.

**Operator gate** (emulated rehearsal): lab-sno on a libvirt host with a pull
secret, recording each phase's duration, with interruption drills during the
bootstrap and install waits. A row accepted before X19 lands is repeated on a
build that contains it, and so is a row accepted before X20: X19 changed the
Redfish effect path ([X19](delivered.md#x19--redfish-and-identity)), and
[X20](delivered.md#x20--substrate-port-pre-boot-proof-and-observations) proves each node before boot, powers a libvirt
node off before booting it and selects its disk at every release. Before
installing such a build, destroy every lab-sno context applied earlier with the
executable that applied it: the media and install requests are now version 3.
The first run on
a build with X22 also confirms that the OpenShift client asset Bootwright
fetches carries the release stamp X22 checks, which is verified only for the
rhel9 tarball. Physical hardware
is not this item's gate; M3's exit tier reaches it through [B67](#b67)
([knowledge](../../.agents/knowledge/openshift-agent-disk-safety.md)).

**Constraints left behind:** administrator access stayed in the installer's
root-owned work area until [X21](delivered.md#x21--bmc-trust-and-administrator-custody) took a copy into context
custody, which `cluster kubeconfig` reveals; an artifact server on another
Machine refuses; `render installer` stays unavailable ([B52](m7.md#b52)); the
controller's resolver is proved, not configured, so the operator routes the
managed zone; disconnected installation waits for a managed `Registry`
([B68](m1.md#b68), [B69](#b69)); and a destroyed cluster's physical nodes keep
running ([B70](m1.md#b70)).

Since X29 a client without its release stamp refuses with a remedy naming the release-stamp check. The stamp is verified only for the rhel9 tarball, so if the `openshift-client-linux` archive Bootwright fetches carries none, every OpenShift client install refuses and no mirror or release change passes; this item's operator run checks it.
