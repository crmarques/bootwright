# M3 — OpenShift clusters on bare metal

Provision and destroy OpenShift clusters on bare metal: nodes behind BMCs,
emulated by libvirt guests behind sushy-tools Redfish BMCs or physical. The
[product scope](../project.md#product-scope) names bare metal through BMCs and
OpenShift container clusters. The day-2 surface a completed cluster exposes is
a [non-goal](../project.md#design-priorities-and-non-goals) and stays parked
as [B106](backlog.md#b106). Every expansion beyond B61's topology destroys a
completed M1e snapshot before a fresh expanded apply.

**Requires:** M1, whose B1, B3, B5, B6, B9 and B10 these items need; and
[B72](m4.md#b72) in code, under B61's waiver. **Exit tier:** an emulated
rehearsal on libvirt guests behind sushy-tools BMCs and real hardware, each an
owner-accepted acceptance-ledger row (D17). **Open decisions:** none numbered.

X14 to X16 delivered the cluster hardening that made B61's operator gate
runnable, under their own IDs in [delivered](delivered.md).

## Item detail

### B61

**Owners:** Container cluster and Substrate, with Infrastructure services,
Controller, Secrets and State reconciliation; using Machine. **Requires:**
[B72](m4.md#b72), waived on explicit request on 2026-09-16. **Acceptance
baseline:** `8aa4494`, where X11 landed. The agent-installer part of M3,
without [B52](m2.md#b52)'s `render installer`, [B59](m2.md#b59) or
[B70](#b70).

**Deviation.** A physical cluster node refuses before registration:
[B6](m1.md#b6) repairs the pre-boot target proof and [B67](#b67) lifts the
refusal. From 2026-09-26 the operator gate could not pass, because the install
identity came from a `metadata.json` the agent installer never writes and the
served image was unreadable by the artifact server; X14 to X16 repaired both,
so the gate can run again.

**Descoped:** the administrator-access custody contract moves to
[B10](m1.md#b10).

**Supported shape.** Nodes that are virtual Machines on a realized substrate;
single-node is the rehearsed topology and multi-node libvirt stays admitted
(D9) under the topology checks X16 delivered. The rest is
[selection and refusal](../container-clusters.md#selection-and-refusal): a
release declared by version, the `agent` method, `connected` mode. OKD,
disconnected mode, FIPS, disk encryption, serving certificates, registry policy
and a release pinned by image alone refuse. Consumer:
[`examples/lab-sno`](../../examples/lab-sno/README.md).

**Capabilities.** [Boot media](../container-clusters.md#boot-media) proves the
installer against the release and builds the agent image from the
[projected inputs](../container-clusters.md#installer-inputs), published
privately because it carries the pull secret.
[Installation](../container-clusters.md#installation) boots each node through
its [substrate's boot operation](../substrates.md#identity-and-power-operations)
and reads the cluster back before releasing the media.

**Exit evidence:** the `containercluster` projection suite (install-config and
agent-config goldens for a single-node libvirt cluster, a multi-node libvirt
cluster and a multi-node physical cluster, the derived platform and rendezvous
address, and the refusals above); the capability suite for both blocks (the
installer-version refusal, private publication removed by the inverse, the
resumable and terminal wait classifications, completion proved against the
cluster's own identity, replay without a rebuild, an inverse that retains the
cluster, quiescence); the substrate boot-operation tests for both arms; the
managed resolver's cluster records; the `examples/lab-sno` acceptance; and
`make check`.

**Operator gate** (emulated rehearsal): lab-sno on a libvirt host with a pull
secret, recording each phase's duration, with interruption drills during the
bootstrap and install waits. A row accepted before X19 lands is repeated on a
build that contains it, because X19 changes the Redfish effect path
([X19](delivered.md#x19--redfish-and-identity)). Before installing a build with X19, destroy every lab-sno
context applied before it with the executable that applied it: its media
request is now version 3. Until [B5](m1.md#b5), one transient Redfish read
failure can end a wait; that is not a boot-path regression. The first run on
a build with X22 also confirms that the OpenShift client asset Bootwright
fetches carries the release stamp X22 checks, which is verified only for the
rhel9 tarball. Physical hardware
is not this item's gate; M3's exit tier reaches it through [B67](#b67)
([knowledge](../../.agents/knowledge/openshift-agent-disk-safety.md)).

**Constraints left behind:** administrator access stays in the installer's
root-owned work area, so no command reveals it and a destroy of the context
takes it with the area ([B10](m1.md#b10)); an artifact server on another
Machine refuses; `render installer` stays unavailable ([B52](m2.md#b52)); the
controller's resolver is proved, not configured, so the operator routes the
managed zone; disconnected installation waits for a managed `Registry`
([B68](#b68), [B69](#b69)); and a destroyed cluster's physical nodes keep
running ([B70](#b70)).

### B67

Physical cluster nodes: lift the physical-node refusal [B61](#b61) keeps, with
its own tests and an emulated rehearsal, and real-hardware acceptance before
support is claimed (D2). [B6](m1.md#b6) delivers the pre-boot proof it builds
on. **Exit evidence:** in-tree tests in place of the refusal test; an emulated
rehearsal; an owner-accepted real-hardware ledger row, which also meets M3's
real-hardware exit tier. X19's Redfish client
assumes from documentation alone what the first physical controller must
confirm: the VmmControl Disconnect payload, the 12 times 5 s boot read-back,
the TaskState rule, the one-authority refusal of firmware that returns absolute
references under its own host name, and the manager-scoped and dual-view
shapes. X19's `deviceName` rule applies to physical nodes once
their refusal lifts.

### B70

Physical offline disk erase and managed-machine destroy on bare metal. Exact
disk identity is unproved during the controller-to-installer interval; it needs
new safety evidence that closes or explicitly bounds it. The physical managed-OS
installation narrowed that interval with an in-installer identity check but did
not close it, and deliberately kept removal retaining: a physical removal
releases its claim and erases nothing
([mutation safety](../state-reconciliation.md#mutation-safety)).
[B78](m4.md#b78) inherits it. **Exit evidence:** a separate safety contract,
an immutable target proof at erase, failure injection and real-hardware
qualification.

### B71

A derived, effect-free `status` handoff section whose
[predicate](../state-reconciliation.md#bootstrap-completion-and-gitops-readiness)
uses facts the code has: the apply is done, every planned block is done, no
unresolved `unknown`, no durable fault. Its definition decides whether block
completion discharges frozen readiness and access requirements, and how a
completed apply whose last write latched the log fault restores it short of a
destroy. **Exit evidence:** status goldens for ready and each unready reason.
