continue and destroy it through [M2b](#m2b)'s minimal virtual cluster,

## Submilestones

M2a to M2e are stable submilestone IDs within M2, introduced on 2026-10-11
(D131). They group definition and delivery outcomes; M2 retains its single
milestone status and its B/X identifiers. A submilestone is not an active
slice and grants no implementation authority. The retired M2a/M2b aliases
from before 2026-09-28 keep their historical meanings; current references
link to the definitions below.

### B628

`internal/storage/ceph/requests.go` admits an absent or `aes`
`security.cephx.keyType`. The research behind D162 found that a 20.2.x cluster
mints new keys as `AES256KRB5` and that `ceph-authtool` defaults to that type,
so a declared `aes` may not be what the cluster holds. It is also the root of
the Data Foundation client question for M4. Confirm it first. **Outcome:**
either a recorded proof that `aes` is the type 20.2.x honors when declared, or a
specified correction of the admitted values with their frozen-request effect.
**Requires:** a 20.2.x guest to read the key type from, which the owner's 9.9.1.2
or 9.9.2.0 run provides; B626. **Definition:** `Needs definition`, with the
question whether a declared type is applied or only recorded. **Exit evidence:**
the observed key type from a live 20.2.x cluster, then a unit test over the
admitted values.
