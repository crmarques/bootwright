# M2 — Full IBM Ceph provisioning

Fully provision, verify, continue and destroy managed IBM Ceph 9.9.x clusters
on libvirt guests behind sushy-tools Redfish BMCs and on physical bare metal
through BMCs. Deliver every provisioning feature available from the IBM Ceph
provider for that release family, including managed RHEL host prerequisites
and storage resources. [B472](#b472) fixes the exact release coordinates and
the complete provider feature matrix before implementation; the existing
typed schema is a starting point, not a limit on the requested coverage.
The [product scope](../project.md#product-scope) owns the bootstrap boundary.

**Requires:** M1. Storage lifecycle planning, ports, native projection and
qualification belong here through [B79](#b79) and [B472](#b472); physical erase
is [B70](#b70). Later milestones reuse these qualified contracts. The install
arms [B74](#b74) to [B77](#b77) need
B73. **Exit tier:** full-cluster emulated rehearsal on libvirt guests behind
sushy-tools BMCs and real-hardware acceptance through BMCs, each an
owner-accepted acceptance-ledger row (D17, D128). Both tiers qualify the
provider feature matrix, continuation, readiness and safe destroy; a host-only
installation or one reduced cluster profile does not complete M2.
**Open decisions:** exact IBM Ceph 9.9.x packages, images, tools and schemas,
provider feature coverage and any required API extensions (B472).

[X38](delivered.md#x38--the-real-host-run-of-2026-10-05) completed B72, managed RHEL on
emulated bare metal, when the owner accepted its run of 2026-10-05 (D58).

[X45](delivered.md), delivered out of sequence on the
owner's request (D60), lifted the refusal of physical installation and delivered
the qualified physical Redfish client; [B73](#b73) and
[B305](#b305) keep their operator gates.

## Item detail

### B70

Physical offline disk erase and managed-machine destroy on bare metal. Exact
disk identity is unproved during the controller-to-installer interval; it needs
new safety evidence that closes or explicitly bounds it. The physical managed-OS
installation narrowed that interval with an in-installer identity check but did
not close it, and deliberately kept removal retaining: a physical removal
releases its claim and erases nothing
([mutation safety](../state-reconciliation.md#mutation-safety)).
[B78](#b78) inherits it. **Exit evidence:** a separate safety contract,
an immutable target proof at erase, failure injection and real-hardware
qualification.

### B73

**Owners:** Substrate and Managed OS, with Infrastructure services, Machine and
State reconciliation. **Requires:** B72, waived on explicit request by
2026-09-16 and completed by [X38](delivered.md#x38--the-real-host-run-of-2026-10-05); X21; X45, delivered; D103 and D104. The
physical installation on B72's Anaconda path, without M3 or
[B70](#b70). **Acceptance baseline:** the commit that delivers X45 and
lifts the physical-installation refusal, the one whose `Refs:` line names X45
and B73 (`git log --grep='^Refs: X45'` finds it).

[X45](delivered.md) delivered the repair of
private host-key delivery over the BMC trust
[X21](delivered.md#x21--bmc-trust-and-administrator-custody) delivered, as D103
chose it, and lifted the refusal; every in-tree gate passes
([record](delivered.md)). The per-machine installer
image is published only under the private token subtree
`private/os/<machine>/<token>/` and withdrawn before the completion inspection;
private delivery requires a controller leg that is https with its certificate
verified; the delivered host key is installed at its own type's path and the
controller's connection pins that type.

**Supported shape.** A bare-metal `InfraProvider` whose Machines declare NICs,
boot NIC, management controller and root device, install through
`redfishVirtualMedia` and name the delivered `sshKeyPair`; `substrates` may be
empty and virtual and physical Machines may mix. The
[managed-OS refusal table](../managed-os.md#refusal-table)'s refusals stand.
`import-certificate` trust, implemented since X21, is proved only in-tree, and
a BMC that publishes no Certificates collection needs
`established`, the operator importing the media CA out of band until
[B319](#b319) (D104).

**Capabilities.** One [target derivation](../substrates.md#selection-and-refusal)
every consumer reads, so `machine start` honours `bmc.tls.verify`;
[physical realization](../substrates.md#physical-machine-realization), which
proves identity and MAC set and retains everything on removal; and
[physical installation](../managed-os.md#physical-installation), which consumes
`data-loss` on apply, re-proves the target before and inside the installer and
proves completion over SSH pinned to the key its
[private publication](../infrastructure-services.md#private-consumer-publication)
delivered.

**Remaining, the operator gate** (emulated rehearsal): the
[lab-baremetal](../../examples/lab-baremetal/README.md) rehearsal on a build
that descends from the baseline, first proof of the emulator's
`EthernetInterfaces`. It cannot run until X47 delivers [B446](#b446): the
emulated controller serves plain HTTP, and a private delivery refuses an
unverified controller leg (D103, D120). The owner's accepted ledger row
completes the item. [B78](#b78) qualifies the physical host; [B80](#b80) and
[B81](#b81) supply M2's full-cluster real-hardware acceptance (D17, D128)
([knowledge](../../.agents/knowledge/redfish-physical-bmc.md)). D60 sets the
runs that follow X45: a disposable qualified controller, this rehearsal, then
one physical BMC observation ([B305](#b305)). Firmware premises and unverified
protocol behavior are tracked in the
[Redfish knowledge](../../.agents/knowledge/redfish-physical-bmc.md); local
machine observations and the selected test hardware remain in ignored notes.

The identity inspection documents no worst case: it makes one request per reported network interface, which the managed-OS margin covers only up to six interfaces (X26).

**Constraints left behind:** a
[residual race](../state-reconciliation.md#mutation-safety) between the last
controller proof and the installer's first write; physical destroy and erase
remain [B70](#b70), so removal retains the system; FIPS profiles refuse
as the [managed-OS refusal table](../managed-os.md#refusal-table) lists
([B75](#b75)), and since
[B289](delivered.md#x41--lifecycle-results-the-controller-stage-installation-shapes-and-bounded-runs)
a bonded or VLAN install interface refuses before registration as that table
lists ([B74](#b74)); two contexts claiming one controller from
different hosts are not coordinated; a failed attempt leaves its private
subtree published until the next apply clears it or a destroy removes it (D122);
and a host-key type the controller's crypto policy excludes fails the
reachability proof, not a refusal before it ([B448](#b448)).

Since X21 a physical Machine's virtual media defaults to `import-certificate`, whose import, settlement and restore flow, and the controller CA bundle as the only anchor, are proved only in-tree against the upstream sushy-tools and DMTF shapes; this item's acceptance runs qualify them on firmware. A manager-scoped virtual-media device that publishes no Certificates collection needs `established`; `disable-verification` writes nothing there ([B447](#b447)).

### B318

Nothing checks the controller host's firewall for Bootwright's listeners, so a
BMC or installer that a default zone blocks meets an opaque
`ConnectionFailed` while readiness, probing over loopback, passes (found by
the 2026-10-05 audit). The operator owns the firewall, and the docs list the
ports by source (D110); before [B78](#b78), `preflight controller --context`
and `plan` report, for each declared socket, whether the zone of its
endpoint's interface admits the port. Its definition decides whether a closed
port warns or refuses before registration. **Exit evidence:** preflight and
plan tests over a fake zone query, for an open and a closed port.

### B446

### B447

D121 amends D104. Where a manager publishes `HttpsTransferCertVerification`,
that switch alone decides whether the read-back before a private insert passes,
and the device's `VerifyCertificate` counts only on firmware whose manager
publishes no such switch. The qualified firmware variation has a read-only device flag and answers a
PATCH with 501 `PropertyModificationNotSupported`; D104 originally refused
its private delivery (found in X45). On the same firmware `disable-verification` writes nothing, because the
device's flag already reads false and is read-only while the manager's switch
decides, so an operator who declares it is told nothing and the insert proceeds
under whatever the switch holds; it should refuse, naming the manager's switch.
A capture of the device's flag after the manager's switch is on stays an
operator item for [B305](#b305)'s observation. **Exit evidence:** Redfish client
tests over the qualified firmware shape for a switch that reads true with the device false
(passes), a switch that reads false (refuses before any write), a manager with
no switch (the device decides), and `disable-verification` on a device that
reads false and cannot be written (refuses naming the manager's switch); the
substrates and machines specs and the knowledge page stating the rule; and D104
marked as amended.

### B448

X45 installs a delivered host key at its own type's path and pins the
controller's connection to that type, but a controller whose crypto policy
excludes the type of the delivered host key, or of the fleet key the
installation authorizes, still waits for the installation and then fails the
reachability proof, where it should refuse before anything runs, naming the
Secret and its key type (rsa or ecdsa-p256 under FIPS); the reachability task
with an empty pinned host key also fails on an unsupported type with no name
(found in X45, the half of F-035 that X39 left). [B346](backlog.md#b346) asks
the same of the libvirt identity path. **Exit evidence:** a refusal before the
reachability wait that names the Secret and its key type for each excluded
type, a test over a controller policy that excludes it, and a failure that
names an empty pinned key as empty.

### B449

The managed-OS run margin's controller-insert bound, which X45 lengthened for
the release before the first attach and the verification reads, still omits the
requests an `import-certificate` insert makes to set the media trust: up to the
certificate collection's 8 members and 5 more requests, plus one 412 retry,
about 7 minutes at the 30 second request timeout, which the module's
documentation counts separately (found in X45; the omission is older). An apply
whose trust is `import-certificate` can therefore reach its deadline while the
controller still answers. **Exit evidence:** the bound counting those
requests, the margin test and the managed-OS spec's stated figures moved with
it, and a test that fails when a step of the insert is omitted from the bound.

### B472

release-specific capabilities, recording exact package, image, tool and native
schema coordinates. Map each feature to typed intent, lifecycle planning,
native inputs, bounded effects, readiness, access, continuation, secret custody
and safe removal. Qualify every provider-supported topology, deployment and
security option, host prerequisite and storage-resource family; identify and
deliberately extend API gaps rather than silently reducing scope. Break the
matrix into bounded implementation items and slices before promotion.
Managed native inputs are frozen lifecycle data; [B55](m7.md#b55) and
[B56](m7.md#b56) later reuse their qualification for standalone publication.
**Exit evidence:** a complete feature-to-contract-and-gate matrix, bounded
implementation items for every gap, qualified native schema and defaults,
deterministic projection goldens, secret binding and non-disclosure tests and
negative effect tests. B80 and B81 subsequently supply full-cluster acceptance
covering the matrix at both M2 operator tiers.
