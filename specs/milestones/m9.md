## Item detail

### B733

Consume the [node substrate port](../openshift-clusters.md#nodes-on-kubevirt-and-vsphere)
and [installer inputs](../openshift-clusters.md#installer-inputs).
The nodes select one vSphere provider and may use multiple placements.
Use a provider-neutral media delivery contract that passes private per-node
media to its target. The cluster installer contributes no hypervisor SDK calls
or client-specific transfer flags. Mixed-provider clusters stay parked in
[B747](backlog.md#b747).

Project [platform intent](../api/openshift-clusters.md#platform-union-and-derivation)
for single node or an external load balancer on platform none and multi-node
vSphere using installer-owned VIPs. The Bootwright endpoint source maps to the
installer's native values. For credentialed installs, derive the used vCenters,
ports and failure-domain topology from node placements, cluster-owned region
and zone declarations and NIC backing. Validate completeness and ambiguity. A
separate in-cluster effect credential is explicitly bound, substituted only at
attempt time and verified over trusted TLS. Its presence inside the private
agent image bounds staging permissions and cleanup. A credential-free install
omits vcenters and failureDomains. Provisioning access remains separately
rebindable. CSI/CNS volumes created by the cluster are reported as retained.

**Exit evidence.** Goldens cover three- and five-node profiles in both credential
modes, the single-node and external-load-balancer cases, multiple placements
and custom ports. Prove credential substitution and absence from records,
failure before upload for untrusted TLS, invalid credentials or incomplete
topology, targeted per-node release, interruption and bounded recovery.
Each distribution enables this path only on passing its own workload gate.

### B734

On vCenter/ESXi 8.0 U3 run the [vSphere acceptance profiles](../openshift-coverage.md#acceptance-profiles).
Qualify both credential modes, cluster readiness and access (including CSI
provisioning with credentials), separation of credentials, image release,
settle and safe destroy. Interrupt upload and each installer wait. Record
versions, hardware, placement, phase durations, bounds, cleanup of all owned
VMs and private media, and retained external volumes. Repeat both credential
modes on 9.x. Use sanitized ledger entries and private raw evidence.

### B1916

### B1917

Consume provider-owned disk evidence through the [Ceph host and device
qualification](../ceph-coverage.md#profiles-and-capacity). Map placement and
physical failure domains explicitly. Match device and backing identities
through vCenter, the guest and Ceph before OSD creation or removal. Replace
any libvirt-only witness dependency at its owner. Qualify ordinary VMDKs for
lab profiles separately from IBM production raw device mappings. Production
qualification requires the applicable IBM support conditions, dedicated hosts,
direct LUN identity, an exclusive backing witness and explicit retention or
cleanup of guest metadata. VM removal must preserve raw LUNs. Verify the chosen release against the [IBM Storage Ceph compatibility matrix](https://www.ibm.com/docs/en/storage-ceph/9.9.0?topic=compatibility-matrix).

For IBM and upstream, enumerate applicability of P1–P7, including the
[stretch constraints](../ceph-coverage.md#stretch-constraints), before enabling
each distribution. Run the applicable matrix on 8.0 U3 and a core and stretch
smoke on 9.x. Exit requires healthy placement groups and quorum, verified I/O,
failure-domain loss and recovery for stretch, replay, absence of owned
resources and positive preservation of external backing. A production claim
requires release-specific support evidence and a matching operator run.
